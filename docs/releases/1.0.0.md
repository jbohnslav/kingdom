# Kingdom 1.0.0 release notes

> **Pre-cut status:** these notes describe the intended 1.0.0 tree. The checkout
> remains at 0.6.x while release gates are open; this document is not a tag,
> package publication, or claim that the final version cut has passed.

Kingdom 1.0 makes the durable ticket loop the primary workflow and treats
autonomous orchestration as an optional layer. Existing ticket Markdown remains
the source of truth throughout the upgrade.

## What stayed

- `kd tk pull` remains the supported way to select backlog work onto the active
  branch. Pulling with `--start` binds only the calling execution context.
- The council chat TUI remains supported as `kd council chat`; it was not removed
  merely to reduce the command count.
- Peasant workers still enter independent council review by default. The faster
  native-subagent path does not weaken that reviewed-worker default.

## What changed

- **Session-scoped current tickets:** `kd tk start` and `kd tk current` bind work
  to an exact execution context, so concurrent agents on one branch can own
  different tickets. `kd status` and TUI `/status` expose those contexts.
- **Typed closure reasons:** `kd tk close` records `completed`, `wont-do`,
  `duplicate`, `superseded`, or `invalid`. Non-completed outcomes require a
  reason, references are validated, and `kd done` reports the same breakdown in
  human and JSON output.
- **Optional design:** tickets and epics no longer require a design document or
  breakdown. Existing design state remains readable and `kd design` remains
  callable when the extra artifact is useful.
- **Command consolidation:** `kd tk log` is the canonical attributed Worklog
  append path. `kd tk defer --reason` returns selected work to backlog, while
  `kd tk pull` selects it again. The long `ticket` route and short `tk` route
  share one implementation; optional `design` and internal `hook` stay callable
  without crowding root help.

## Upgrade and rollback

Follow the [upgrade and rollback guide](../upgrading.md), not an ad hoc ticket
rewrite. In summary:

1. stop active Kingdom sessions and copy `.kd` to a timestamped backup;
2. update the CLI and integrations;
3. run `kd tk current` in each context to perform the lazy exact-context
   migration;
4. run the read-only `kd doctor` and resolve any ambiguity before continuing;
5. retain the legacy context state and backup until the upgraded workflow passes.

Migration preserves ticket IDs, unknown frontmatter, Markdown bodies, Worklogs,
backlog tickets, and archived tickets. The guide documents recoverable rollback
of runtime context state, the installed CLI, or the complete `.kd` directory.

The dated [supported host integration matrix](../support-matrix.md) distinguishes
live evidence from deterministic contracts and keeps Cursor's known lifecycle
limits explicit.

## Staged deprecation boundary

The 0.6.x pre-cut tree still contains two compatibility paths so their warnings
and migrations can be verified. Neither belongs in the final 1.0.0 public CLI:

| 0.6.x compatibility path | Supported replacement | Final 1.0.0 state |
| --- | --- | --- |
| `kd tk move` | backlog to work: `kd tk pull`; work to backlog: `kd tk defer --reason`; branch to branch: defer, switch, then pull | Remove the public command. Keep the internal file-move primitive used by supported workflows. |
| hidden `kd tk add-note` | `kd tk log`, using stdin or direct Markdown editing for command-rich/multiline notes | Remove the alias. Its v0.8.0 removal boundary is necessarily crossed by the direct 0.6.x to 1.0.0 release. |

The final version-cut ticket must prove both public routes are absent before it
changes package version surfaces to 1.0.0.

Cursor limitations classified in the support matrix are the deliberate supported
boundary rather than unresolved regressions. Other backlog enhancements were not
discovered by this epic's dogfood and are not release blockers.

Two explicitly deferred items are not correctness regressions: [`ff67`](../../.kd/backlog/tickets/ff67.md)
is a future transactional migration capability to design only when a concrete new
schema needs it, while [`0cb0`](../../.kd/backlog/tickets/0cb0.md) is optional
presentation work for role-flavored context names. Neither expands the 1.0 cut.

After the issues above are disposed, run the full suite, Ruff, documented smoke,
and manual CLI/TUI review on the integrated tree with no waived failures. Close
the release tickets and epic, pass `uv run kd done` on the live branch, then build
and validate release artifacts without publishing.
