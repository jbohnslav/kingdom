# Kingdom 1.0.0 release notes

Kingdom 1.0 makes the durable ticket loop the primary workflow and treats
autonomous orchestration as an optional layer. Existing ticket Markdown remains
the source of truth throughout the upgrade.

## What stayed

- `kd tk pull` remains the supported way to select backlog work onto the active
  branch. Pulling with `--start` binds only the calling execution context.
- The council chat TUI remains supported as `kd council chat`; it was not removed
  merely to reduce the command count.
- Peasant workers still enter independent council review by default. The faster
  native-subagent path does not weaken that reviewed-worker default.

## What changed

- **Session-scoped current tickets:** `kd tk start` and `kd tk current` bind work
  to an exact execution context, so concurrent agents on one branch can own
  different tickets. `kd status` and TUI `/status` expose those contexts.
- **Typed closure reasons:** `kd tk close` records `completed`, `wont-do`,
  `duplicate`, `superseded`, or `invalid`. Non-completed outcomes require a
  reason, references are validated, and `kd status --check` reports the same
  readiness breakdown without mutating workspace state.
- **Optional design:** tickets and epics no longer require a design document or
  breakdown. Existing design state remains readable and `kd design` remains
  callable when the extra artifact is useful.
- **Command consolidation:** `kd tk log` is the canonical attributed Worklog
  append path. `kd tk defer --reason` returns selected work to backlog, while
  `kd tk pull` selects it again. The long `ticket` route and short `tk` route
  share one implementation; optional `design` and internal `hook` stay callable
  without crowding root help.
- **Workspace lifecycle:** `kd start [branch]` initializes, resumes, or selects a
  workspace. `kd status --check` derives readiness from terminal ticket state;
  there is no separate branch-finalization transition or force bypass.

## Upgrade and rollback

Follow the [upgrade and rollback guide](../upgrading.md), not an ad hoc ticket
rewrite. In summary:

1. stop active Kingdom sessions and copy `.kd` to a timestamped backup;
2. update the CLI and integrations;
3. run `kd tk current` in each context to perform the lazy exact-context
   migration;
4. run the read-only `kd doctor` and resolve any ambiguity before continuing;
5. retain the legacy context state and backup until the upgraded workflow passes.

Migration preserves ticket IDs, unknown frontmatter, Markdown bodies, Worklogs,
backlog tickets, and archived tickets. The guide documents recoverable rollback
of runtime context state, the installed CLI, or the complete `.kd` directory.

The dated [supported host integration matrix](../support-matrix.md) distinguishes
live evidence from deterministic contracts and keeps Cursor's known lifecycle
limits explicit.

## Removed and consolidated commands

Four redundant or compatibility paths were removed from the 1.0.0 public CLI:

| Removed command | Supported replacement | 1.0.0 behavior |
| --- | --- | --- |
| `kd done` | `kd status --check` | Readiness is derived without writing branch state, clearing a global pointer, cleaning unrelated resources, or exposing a `--force` bypass. |
| `kd switch <branch>` | `kd start <branch>` | One idempotent entry point initializes, resumes, or selects a workspace. |
| `kd tk move` | backlog to work: `kd tk pull`; work to backlog: `kd tk defer --reason`; branch to branch: defer, check out the target, run `kd start <branch>`, then pull | The public command is absent. The internal file-move primitive remains available to supported workflows. |
| hidden `kd tk add-note` | `kd tk log`, using stdin or direct Markdown editing for command-rich/multiline notes | The alias is absent. The direct 0.6.x→1.0.0 release crossed its previously announced v0.8.0 removal boundary. |

These replacements preserve ticket Markdown and Worklog history. Cleanup remains
with the resource owner: ticket close/defer operations clear ticket bindings,
`kd status --prune-stale` removes stale contexts, and peasant accept/clean/prune
manage worker resources.

## Resolved correctness issues

The release audit treated the following dogfood findings as blockers rather
than accepted 1.0 limitations. Each linked ticket is now closed with reviewed
regression evidence:

| Issue | Observed behavior | Resolution |
| --- | --- | --- |
| [`14fa`](../../.kd/branches/codex-workflow-polish/tickets/14fa.md) | Human and JSON status assignments presented closed historical assignees as current work. | Status now excludes closed assignments in both formats. |
| [`063d`](../../.kd/branches/codex-workflow-polish/tickets/063d.md) | Exact-owner `tk log` activity did not refresh context `last_seen`, so diligent long-running owners looked stale. | Exact-owner activity refreshes its context; foreign activity cannot keep it live. |
| [`a298`](../../.kd/branches/codex-workflow-polish/tickets/a298.md) | Command-rich notes in a double-quoted shell argument could execute Markdown backticks before Kingdom saw the text. | Prominent guidance and CLI help route rich notes through a quoted stdin heredoc or direct Markdown editing. |
| [`b245`](../../.kd/branches/codex-workflow-polish/tickets/b245.md) | Completed, failed, and stopped peasant rows continued accumulating elapsed time. | Terminal elapsed time freezes at recorded last activity with controlled-clock coverage. |
| [`d88b`](../../.kd/branches/codex-workflow-polish/tickets/d88b.md) | The uv and pre-commit Ruff versions formatted the same assertion differently. | Both paths use Ruff 0.15.0 and the all-files hooks proved no-rewrite behavior. |
| [`50df`](../../.kd/branches/codex-workflow-polish/tickets/50df.md) | `kd status` computed ready counts from branch-local dependencies while canonical ticket listing used global state. | Human and JSON status now use the canonical global dependency lookup and shared filter. |
| [`2d38`](../../.kd/branches/codex-workflow-polish/tickets/2d38.md) | `kd start` swallowed the deliberate legacy `.kd/runs/` error and presented an unsafe fresh-init path. | Only genuine missing state auto-initializes; incompatible legacy state remains a hard error. |
| [`bc0c`](../../.kd/branches/codex-workflow-polish/tickets/bc0c.md) | A non-recoverable peasant authentication failure consumed repeated iterations instead of failing fast. | Authentication/permanent failures stop once, transient retries are bounded, and final status records the infrastructure cause. |
| [`f240`](../../.kd/branches/codex-workflow-polish/tickets/f240.md) | `kd peasant accept` rejected an exact reviewed worker solely because the logical Kingdom feature differed from the checkout branch. | Acceptance now requires one exact reviewed session and merge source while treating the invocation checkout as the explicit integration target. |

## Artifact validation and publication

Artifact validation is performed separately from this documentation. The release
procedure verifies the integrated tree, runs the full suite, Ruff, documented
smoke, host matrix, and `kd status --check`, then installs the built wheel in a
clean environment. The clean-wheel gate covers the `64a8` runtime-dependency
finding and checks the installed `kd --version` surface.

Merging a `pyproject.toml` version bump to `master` automatically runs those
checks, creates the matching tag and GitHub Release, and publishes the validated
artifacts to PyPI. A matching-version manual dispatch remains available only to
recover a missed automatic release.

Cursor limitations classified in the support matrix are the deliberate supported
boundary rather than unresolved regressions. Other backlog enhancements were not
discovered by this epic's dogfood and are not release blockers.

Two explicitly deferred items are not correctness regressions: [`ff67`](../../.kd/backlog/tickets/ff67.md)
is a future transactional migration capability to design only when a concrete new
schema needs it, while [`0cb0`](../../.kd/backlog/tickets/0cb0.md) is optional
presentation work for role-flavored context names. Neither expands the 1.0 cut.

Artifact checks and publication retain their own durable workflow evidence;
they are not inferred from this document.
