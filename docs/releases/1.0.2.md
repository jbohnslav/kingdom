# Kingdom 1.0.2 release notes

Kingdom 1.0.2 makes ticket filing and relocation explicit and prevents colliding
IDs from silently selecting the wrong ticket.

## Ticket safety

- Reject ambiguous ticket IDs across branch, backlog, and archive locations,
  listing each matching board, title, and path.
- Restore `kd tk move <id> --to-branch <branch>` for relocation from a branch,
  backlog, or archive to an existing board. Closed tickets stay closed.
  Moves preserve the complete ticket file, including status, closure
  evidence, custom frontmatter, relationships, and formatting.
- Refuse moves that conflict with active native or peasant ownership. Clean up
  source lock files while keeping waiting writers synchronized.
- Show the actual filing board when creating a ticket and support
  `kd tk create --branch <branch>` without switching the current workspace.

Deferral still intentionally resets work to open/unassigned and refuses closed
work. Use `move` to relocate a ticket whose state must be preserved.

## Workspace and skill guidance

- Surface Git/Kingdom branch mismatches in status output with shell-quoted
  recovery commands that preserve the branch name as a literal argument.
- Run skill context discovery for new requests, branch changes, or ownership
  changes, rather than repeating it on routine follow-ups.
- Reserve `uv run kd` for Kingdom's own source checkout; use installed `kd` in
  every other repository, including Python/uv projects.

## Verification

Regression coverage includes ambiguous-ID reads and mutations, byte-preserving
relocation, lock replacement races, explicit filing boards, and branch mismatch
reporting. Release preparation runs the full test suite, pre-commit checks, and
the documented CLI smoke workflow.
