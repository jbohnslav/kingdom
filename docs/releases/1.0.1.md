# Kingdom 1.0.1 release notes

Kingdom 1.0.1 hardens Council workflows across sessions and repository states.
This release was developed as an explicit dogfooding epic to validate the
post-1.0.0 Kingdom workflow while using `kd` to build `kd`.

## Council reliability

- Return concise, actionable errors when Council commands have no active
  session.
- Make Council reviews account for committed, staged, and unstaged tracked
  changes while clearly warning about untracked files.
- Preserve queued Council chat across process restarts and deliver messages in
  FIFO order.

## Configuration and diagnostics

- Resolve canonical project configuration from linked worktrees, honor
  `KD_BASE`, and fail loudly when configuration is invalid.
- Report doctor status only for configured agents, including missing binaries,
  version failures, runtime failures, and authentication failures.
- Keep provider catalog checks informative without pinning a catalog snapshot.

## Verification

The dogfooding epic exercised the post-1.0.0 ticket lifecycle, durable worklogs,
multi-agent execution, Council review paths, and release-readiness checks.
