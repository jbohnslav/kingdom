# Council queries should create new threads by default

When an agent (e.g. peasant) runs 'kd council ask', it reuses the existing thread for that branch. If a human is actively chatting with the council in an interactive window, the agent's query overwrites the conversation in real time — you can literally watch it happen. Council queries should default to creating a new thread so they don't stomp on active conversations. The current thread could be an explicit --thread/--continue flag instead.
