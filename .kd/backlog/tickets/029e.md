# Hand rethink: first-class Hand identity with multi-hand support

The Hand was originally a core concept but became loose over time. It's still useful — it's the agent the King directly supervises, as opposed to peasants (autonomous) and lords (supervisors). But the current model assumes one Hand. In practice you might want multiple: a Claude hand on one tricky ticket, a Codex hand on another, while a lord manages bug fixes in parallel. Rethink the Hand as a first-class concept: session identity, assignee tracking, multi-hand support, and how it relates to lord/peasant roles.

## Acceptance Criteria

- [ ] Hand sessions have explicit identity (like peasants have peasant-<id>)
- [ ] Multiple hands can work concurrently on different tickets
- [ ] kd tk start assigns to the active hand session
- [ ] kd status / kd tk list shows hand assignments distinctly from peasant assignments
