# PR #33 reviews: Claude and Codex

GitHub reviews on https://github.com/jbohnslav/kingdom/pull/33

## Codex (inline comments)

### P2: Reject malformed `--priority` values instead of defaulting to P2

`src/kingdom/cli/ticket.py:361`

Changing `ticket_create` to accept `priority` as `str` and then passing it through `clamp_priority` makes malformed input like `kd tk create ... -p foo` succeed silently as priority 2, whereas the previous typed `int` option surfaced this as invalid CLI input. This can hide user typos and create incorrectly prioritized tickets without any warning; the command should validate `0-3`/`p0-p3` and fail fast for anything else.

### P2: Diff peasant commits against session branch instead of HEAD

`src/kingdom/cli/peasant.py:549`

Using `HEAD..ticket/<id>` makes `kd peasant show` output depend on whichever branch the operator currently has checked out, so running it from `main` or another unrelated branch can include or exclude commits that are not the peasant's work for the active session. Since `ctx.feature` is already resolved, the left side of the range should be anchored to that session branch (or its merge-base) to keep commit summaries accurate.

## Claude (full review)

Overall: clean, well-tested PR. Three issues, two nits.

### Issues

**1. Unused `backend` parameter in `filter_agent_log_lines`** (`src/kingdom/cli/peasant.py:576`)

`backend` is declared in the signature but never referenced in the function body. The call site at line 532 doesn't pass it either. Dead code — implies the function varies behavior by backend, but it doesn't.

**2. `get_agent_state` called twice in `peasant_show`** (`src/kingdom/cli/peasant.py:508,544`)

Second fetch overwrites the first. If state changes between calls (e.g., peasant finishes during display), they could disagree. Hoist to a single call at the top.

**3. `Ticket` docstring stale after 0-3 priority range expansion** (`src/kingdom/ticket.py:49`)

Comment says "1-3, 1 is highest" but `clamp_priority` now accepts 0-3.

### Nits

**4. Activity ordering may interleave poorly** (`src/kingdom/cli/peasant.py:534`)

`activity = plain_lines + stream_lines` — both from the same log file but assembled differently. Not a bug, just worth a comment explaining ordering rationale.

**5. `kd update` exits 0 on skill refresh failure**

When `uv tool upgrade` succeeds but `install_skill()` fails, the command prints a warning and exits 0. Consider whether this should exit 1 — user may not notice skills are stale.

### What's good

- `kd update` well-structured with proper error handling
- Skill symlink refactor cleanly eliminates duplication, regression test validates both symlink and content-equality
- Commit range `HEAD..branch_name` is correct, explicitly tested
- `clamp_priority` handles `p0-p3` case-insensitively with good edge case coverage
- `reassemble_stream_text` is a pure function — easy to test
- Ticket-First Reflex section is clear and actionable
- Solid test coverage across all three features
