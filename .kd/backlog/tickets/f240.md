# Allow peasant accept when the logical kd branch differs from the checkout

## Acceptance Criteria

- [ ] `kd peasant accept <ticket>` resolves the reviewed ticket branch and
  recorded Kingdom feature without requiring the checkout's Git branch name to
  equal the feature key.
- [ ] Acceptance still refuses ambiguous or unsafe targets and never merges an
  unrelated ticket branch.
- [ ] A deliberate logical-feature/checkout mismatch has regression coverage.
- [ ] The error path offers a safe exact recovery command when automatic
  acceptance cannot proceed.

## Context

Dogfooding `92ca` on 2026-08-03 produced a council-approved commit on
`ticket/92ca`, but `kd peasant accept 92ca` refused because `.kd/current` named
`codex/workflow-polish` while the intentionally busy checkout was on `master`.
The ticket and peasant session were exact, so the branch-name equality check
turned Kingdom's logical grouping into an unnecessary Git-layout constraint.
