# Add transactional repository upgrade and rollback commands

The v0.6 migration remains intentionally lazy, but future schema changes may
need an explicit transaction. Design a generic upgrader only when a concrete
next schema requires it, with a manifest, byte-for-byte backup, atomic commit,
and a rollback command that refuses ambiguous or modified state.

## Acceptance Criteria

- [ ] A versioned migration manifest defines the exact source and target schemas.
- [ ] Upgrade creates and verifies a complete backup before changing `.kd`.
- [ ] Interrupted upgrades resume or roll back without losing ticket Markdown.
- [ ] Rollback refuses to overwrite post-upgrade edits without explicit recovery.
- [ ] Mixed branch, backlog, archive, and runtime fixtures prove round-trip safety.
