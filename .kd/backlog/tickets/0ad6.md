# Do not auto-bind fresh worker contexts to an unassigned epic

During post-1.0.0 native-subagent dogfooding, a fresh explicit `KD_CONTEXT`
ran `uv run kd tk current` as part of context discovery. Legacy-binding migration
auto-selected `b1de` solely because it was the only unassigned `in_progress`
ticket, even though it was an epic umbrella rather than an atomic worker ticket.
Starting child `478a` then silently unassigned the epic and rebound that context.

## Acceptance Criteria

- [ ] `kd tk current` does not auto-bind a fresh execution context to an unassigned epic.
- [ ] Legacy migration considers only atomic worker tickets and reports ambiguity without mutating ownership.
- [ ] Starting a different ticket from an already-bound context either rejects with an exact recovery path or requires an explicit transfer.
- [ ] Regression coverage reproduces the fresh-context, unassigned-epic discovery sequence.
