# Align kd status ready counts with global dependency state

`kd status` currently builds its dependency lookup only from the active branch,
while `kd tk list --ready` and the ticket-first `kd start` path use global active,
backlog, and done ticket state. A current-branch ticket whose dependency closed
elsewhere can therefore be counted blocked by status but ready by canonical list.

## Acceptance Criteria

- [ ] Human and JSON status ready counts use the same dependency semantics as `kd tk list --ready`.
- [ ] A regression covers a current-branch ticket depending on a closed ticket in another active or done location.
- [ ] Existing status output and execution-context tests remain green.
