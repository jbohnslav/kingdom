# Add --watch flag to kd peasant start

## Context

After `kd peasant start`, the King almost always wants to watch progress.
Today that's two commands: `kd peasant start <id>` then `kd peasant watch <id>`.
A `--watch` flag on start collapses this into one step.

We intentionally do NOT auto-watch by default. Coding agents run
`kd peasant start` and expect it to return immediately. A blocking watch
loop would cause timeouts or accidental Ctrl+C kills. The default stays
non-blocking; `--watch` is a human convenience flag.

## Implementation

Add a `--watch` / `-w` flag to `peasant_start()` (and `peasant_start_hand()`
if it exists). When set, after the peasant process is spawned successfully,
call `peasant_watch()` inline (or the equivalent watch loop) instead of
returning.

The flag should come after the existing options. Default is False.

## Acceptance Criteria

- [ ] `kd peasant start <id> --watch` spawns the peasant then enters watch mode
- [ ] `kd peasant start <id>` (no flag) behaves exactly as today — returns immediately
- [ ] `--watch` / `-w` flag works on both `peasant start` and `peasant start --hand`
- [ ] Watch mode exits cleanly on Ctrl+C without killing the peasant process
- [ ] Tests cover: start with --watch calls watch, start without --watch does not
- [ ] No TTY detection or auto-watch logic — the flag is explicit
