# Lord mode: autonomous supervisor agent for managing peasant workflows

A supervisor agent mode (lord/steward) where the king delegates an agent to manage a group of peasants working on a feature/epic. The lord would:

- Accept a set of tickets (or an epic) to oversee
- Start peasants on unblocked tickets
- Monitor peasant progress (poll kd status periodically, or event-driven)
- Review completed work when peasants finish (needs-king-review → auto-review)
- Start peasants on newly-unblocked tickets as dependencies close
- Run autonomously with configurable sleep/poll intervals instead of inline bash sleep hacks
- Report status summaries to the king on demand or at milestones

This replaces the current manual workflow of: start peasants → sleep/poll → review → accept → start next batch. The lord should handle the full inner loop automatically while the king focuses on high-level decisions.

## Acceptance Criteria

- [ ] kd lord start <ticket-ids-or-epic> launches a supervisor agent
- [ ] Lord automatically starts peasants on unblocked tickets
- [ ] Lord monitors peasant status and reacts to completion
- [ ] Lord performs basic review of completed work before accepting
- [ ] Lord starts next wave of peasants as tickets unblock
- [ ] Configurable poll interval and review depth
- [ ] kd lord status shows current lord activity and managed tickets
