# Preserve configured Council backends across linked worktrees

Investigate and fix cases where a linked worktree silently falls back to the built-in Claude+Codex council even though the repository is configured to use Cursor instead of Codex. Configuration and its source must resolve consistently from the repository owner across primary and linked worktrees, including environments where a backend is intentionally unavailable by policy.

## Acceptance Criteria

- [ ] Primary checkouts and linked worktrees resolve the same repository Council agents and member order from the canonical config.
- [ ] A configured Cursor member is not silently replaced by the zero-config Codex member when Codex is unavailable or disallowed.
- [ ] Config inspection and doctor output identify the effective config source and selected backends clearly enough to diagnose drift.
- [ ] Regression coverage simulates the primary-checkout and linked-worktree layouts without depending on the developer's home configuration.
