# Record backlog ticket location in terminal context

Codex review found that kd tk start records terminal context with the active branch feature even when the started ticket lives in backlog or archived backlog. update_ticket_status can leave or restore the ticket under .kd/backlog/tickets, but the Stop hook validates terminal context by reading branch_root(base, feature)/tickets, so the just-started backlog ticket is discarded and the hook falls back to kd tk current or fails open.

## Acceptance Criteria

- [x] Starting a backlog or archived-backlog ticket records enough location information for the Stop hook to validate it
- [x] Stop hook prompts for the started backlog ticket instead of falling back when that ticket is in progress
- [x] Regression test covers terminal context for started backlog ticket

## Worklog

- 2026-07-05: Started from Codex review on current head. Existing ticket resolver already returns TicketMatch.location values such as branch:<name>, backlog, and archive:<name>. Plan is to persist that location in terminal context on kd tk start and make Stop hook validation read from the recorded location instead of assuming every started ticket lives under the active branch's tickets directory.
- 2026-07-05: Implemented terminal context location persistence. record_terminal_ticket_context now writes a location, ticket_start records branch/backlog/archive-derived location, and the Stop hook validates terminal context against branch, backlog, or archive paths based on that location. Archived backlog starts record backlog because start restores the ticket before work begins.
- 2026-07-05: Added regressions covering branch context location, backlog context location, archived-backlog restore location, and Stop hook prompt selection for a started backlog ticket. Verification passed: uv run ruff check; uv run pytest -q with 1915 passed, 38 skipped, 1 xfailed.
