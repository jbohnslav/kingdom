# Fix peasant watch

## Problem

The streaming output from 35c3 works but produces fragmented, useless text.
`filter_agent_log_lines()` is showing partial word fragments from NDJSON
stream deltas instead of coherent sentences. Example from a real run:

```
[07:56] and
[07:56] what
[07:56] needs to change
[07:57] . Let me read
[07:57] the key
[07:57] files directly
[07:58] how it
[07:58] handles d
[07:58] iffs.
[07:58] test for
[07:58] this
[07:58] behavior
```

The NDJSON stream emits small text deltas (individual words or fragments).
`extract_stream_text()` faithfully extracts each delta, and the watch filter
shows each one as a separate timestamped line. The result is worse than the
old "Still working..." heartbeats — it's noisy gibberish that's harder to
scan than silence.

## Root Cause

`filter_agent_log_lines()` treats each NDJSON line independently. But
streaming backends emit many small deltas per sentence. The filter needs to
**accumulate** text deltas into coherent lines/sentences before displaying,
not show each 2-3 word fragment as its own timestamped entry.

## Solution

Combine council recommendations: a **pure helper function** that the watch loop
calls with accumulated state, using the poll interval as the natural batch window.

### Architecture

Split into two pieces:

1. **`reassemble_stream_text(buffer: str, new_lines: list[str], backend: str) -> tuple[list[str], str]`**
   — Pure function. Takes the current buffer (carry-over from last poll), new
   raw log lines, and the backend name. Extracts text from NDJSON deltas,
   appends to buffer, splits on real boundaries (newlines, sentence endings),
   returns `(display_lines, remaining_buffer)`. No side effects, easy to test.

2. **Watch loop** owns the persistent `stream_buffer: str` and calls
   `reassemble_stream_text()` each poll cycle. Displays returned lines.
   On agent completion, flushes any remaining buffer.

### Boundary detection

Deterministic, no NLP:
- `splitlines()` first — newlines are authoritative boundaries.
- Within long lines, split on sentence-ending punctuation followed by space:
  `re.split(r'(?<=[.!?])\s+', ...)`.
- Don't emit segments shorter than ~20 chars (avoids "Let me" fragments).
- On final flush (agent done), emit whatever remains regardless of length.

### What happens to `filter_agent_log_lines()`

Keep it for non-NDJSON lines (plain text from agent stderr, tool output, etc.).
The NDJSON reassembly path moves to `reassemble_stream_text()`. The watch loop
calls both: reassemble for stream text, filter for everything else.

## Acceptance Criteria

- [ ] New pure function `reassemble_stream_text()` accumulates NDJSON deltas and splits on real boundaries
- [ ] Watch loop owns `stream_buffer` state, passes it through each poll cycle
- [ ] Watch output shows coherent sentences/phrases, not word fragments
- [ ] Remaining buffer is flushed when agent completes
- [ ] Short fragments (< ~20 chars) are held in the buffer, not displayed
- [ ] The "Still working..." heartbeat still appears when there's genuinely no output
- [ ] `filter_agent_log_lines()` still handles non-NDJSON lines (stderr, plain text)
- [ ] Tests cover: fragmented deltas → coherent sentence, newline boundaries, short fragment buffering, final flush, mixed NDJSON + plain text
