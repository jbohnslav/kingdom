# Fix peasant watch

## Problem

The streaming output from 35c3 works but produces fragmented, useless text.
`filter_agent_log_lines()` is showing partial word fragments from NDJSON
stream deltas instead of coherent sentences. Example from a real run:

```
[07:56] and
[07:56] what
[07:56] needs to change
[07:57] . Let me read
[07:57] the key
[07:57] files directly
[07:58] how it
[07:58] handles d
[07:58] iffs.
[07:58] test for
[07:58] this
[07:58] behavior
```

The NDJSON stream emits small text deltas (individual words or fragments).
`extract_stream_text()` faithfully extracts each delta, and the watch filter
shows each one as a separate timestamped line. The result is worse than the
old "Still working..." heartbeats — it's noisy gibberish that's harder to
scan than silence.

## Root Cause

`filter_agent_log_lines()` treats each NDJSON line independently. But
streaming backends emit many small deltas per sentence. The filter needs to
**accumulate** text deltas into coherent lines/sentences before displaying,
not show each 2-3 word fragment as its own timestamped entry.

## Solution

Buffer extracted stream text and only display when a sentence or line break
is reached. Show the last few **complete** lines/sentences, not the last few
token fragments. The watch output should read like a human summary of what
the agent is doing, not a raw token stream.

## Acceptance Criteria

- [ ] Watch output shows coherent sentences/phrases, not word fragments
- [ ] Accumulated text is split on sentence boundaries or newlines before display
- [ ] Short fragments that don't form a complete thought are buffered, not shown
- [ ] The "Still working..." heartbeat still appears when there's genuinely no output
- [ ] Existing filter tests updated to reflect the new buffering behavior
