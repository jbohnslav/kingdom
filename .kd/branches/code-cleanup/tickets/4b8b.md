# Consolidate duplicated patterns (R5)

## Problem

Several patterns are duplicated across the codebase, making the upcoming CLI split (R2) harder. Consolidating these first means each new module starts clean.

## Acceptance Criteria

### Core three (original)

- [ ] `resolve_ticket_or_exit(base, ticket_id)` helper replaces **all** command-resolution paths (20+ ambiguous-match handlers, not just ~10)
- [ ] `parse_iso_datetime(s)` utility replaces **all** inline `fromisoformat(...replace/endswith)` patterns — tickets, threads, and peasant timestamps
- [ ] `serialize_frontmatter(fields)` shared helper unifies hand-built YAML frontmatter in `ticket.py` and `thread.py`

### Process & naming helpers

- [ ] `is_process_alive(pid: int) -> bool` predicate replaces the 6 copies of `os.kill(pid, 0) / except OSError` across peasant commands (start, status, sync, msg, reject)
- [ ] Peasant naming derivation — `session_name = f"peasant-{id}"` (8 sites) and `thread_id = f"{id}-work"` (5 sites) — consolidated as properties on `PeasantContext` or standalone helpers
- [ ] `create_council(base, feature)` factory replaces the 4-copy setup ceremony (`logs_dir = logs_root(); mkdir(); Council.create(); load_sessions()`) in council_ask, council_reset, council_retry, and worker.py

### Display & serialization dedup

- [ ] Single `STATUS_COLORS` constant — remove the redundant local redeclaration in `ticket_current` and any inline `status_colors` dicts
- [ ] Detailed ticket JSON serialization shared between `tk show --json` and `tk current --json` (currently duplicated)

### Worktree helper

- [ ] `run_init_script(base, worktree_path)` helper replaces the near-identical `init-worktree.sh` run blocks in `create_worktree` and `peasant_sync`

### Gate

- [ ] No remaining duplicated patterns for the cases above
- [ ] All tests pass
