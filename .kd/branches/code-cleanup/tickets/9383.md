# kd council chat: natural mode sends double responses on follow-up messages

## Problem

In natural mode, follow-up messages (anything after the first exchange in a thread)
trigger **two response rounds**: a parallel broadcast followed by shuffled sequential
auto-turns. Each member responds twice per king message.

The intended behavior is:
- **First exchange**: parallel broadcast, no auto-turns (works correctly today)
- **Follow-up exchanges**: shuffled sequential only — each member responds once, in
  random order, able to see the previous member's response

## Root Cause

`run_mode_natural` in `src/kingdom/tui/app.py:834-846` always calls `parallel_query`
first, then `sequential_auto_turns` on follow-ups. On follow-up exchanges it should
skip the parallel broadcast and go straight to shuffled sequential turns.

## Fix

```python
async def run_mode_natural(self, targets, generation, tdir, is_first_exchange):
    if is_first_exchange:
        # First exchange: parallel broadcast, no auto-turns
        await self.parallel_query(targets, generation, tdir)
        return
    # Follow-up: shuffled round-robin only, no initial broadcast
    await self.sequential_auto_turns(generation, tdir, shuffle=True)
```

## Acceptance Criteria

- [ ] First exchange in a thread: both members respond in parallel (unchanged)
- [ ] Follow-up exchanges: members respond once each, sequentially, in random order
- [ ] Each member can see the previous member's response on follow-ups
- [ ] auto_rounds config is respected (default 1 = one round of sequential turns)
