# kd tk create: support full ticket content in a one-liner

## Problem

Every agent (Claude, peasants, etc.) follows the same clunky workflow:
1. `kd tk create "title"` — creates ticket with empty body/AC
2. Try to edit it — fails because they haven't read it yet
3. Read the file
4. Write it back with real content

This is a consistent friction point across every agent interaction. If you already know the title, description, and acceptance criteria, you should be able to create the ticket in one command.

## Current State

A `-d`/`--description` flag already exists, but it has two problems:
1. When used, it replaces the body entirely — the `## Acceptance Criteria` section is lost (`cli.py:3491-3492`)
2. There's no way to specify acceptance criteria separately

So even agents that know about `-d` still can't create a complete ticket in one shot.

## Proposed Solution

- Add a repeatable `--ac` flag for acceptance criteria
- When `-d` is provided, always append the `## Acceptance Criteria` section (don't drop it)
- `--ac` items become checked checkboxes in that section

```bash
kd tk create "fix the bug" \
  -d "Timeout handler doesn't catch FileNotFoundError" \
  --ac "Tests pass" --ac "No regressions"
```

Produces:

```markdown
The timeout handler doesn't catch FileNotFoundError

## Acceptance Criteria

- [ ] Tests pass
- [ ] No regressions
```

## Acceptance Criteria

- [ ] An agent can create a fully-specified ticket (title, body, AC) in one command without needing to read and then edit the markdown file afterward
