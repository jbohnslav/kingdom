# Auto-refresh bundled skill on kd start

After `uv tool update kingdom`, the installed skill files at ~/.claude/skills/kingdom/ stay stale because install_skill() only runs during auto-init (when .kd/ doesn't exist yet).

Fix: on every `kd start`, unconditionally call install_skill() to copy the bundled skill directory. No version tracking needed — the copy is idempotent and takes milliseconds. Skip when the target is a symlink (dev setups).

Implementation:
- In `kd start`, after auto-init block, call `install_skill()` even when `.kd/` already exists
- `install_skill()` already handles the symlink check and copies the whole directory — just call it unconditionally
- No version stamps, no VERSION file, no comparison logic
- Optional: print a one-line notice if files were actually changed (compare content before/after), but not required

Why no version tracking:
- install_skill() copies a handful of small markdown files — always-copy is simpler and equally fast
- No VERSION file to maintain, no importlib.metadata import, no edge cases with corrupted stamps
- The only thing that matters is "skill matches the CLI" — always-copy guarantees that unconditionally

## Acceptance Criteria

- [ ] On `kd start`, always call `install_skill()` to refresh bundled skill files
- [ ] Skip when `~/.claude/skills/kingdom` is a symlink (already handled by install_skill)
- [ ] Refresh the whole skill directory, not just SKILL.md
- [ ] Add a test: `kd start` with stale installed skill → skill directory matches bundled copy
