# Consolidate test fixtures and reorganize tests (R10)

## Problem

Test files mirror the monolithic CLI structure. The `project` fixture is duplicated 8+ times. After the CLI split, tests should be reorganized to match the new module structure.

## Implementation Plan

### Phase 1: Fixture consolidation

Move the duplicated `project` fixture into `tests/conftest.py`. Seven files have
near-identical copies (`test_session.py`, `test_thread.py`, `test_tui_reply.py`,
`test_harness.py`, `test_tui.py`, `test_tui_integration.py`, `test_council.py`).

- Add a `branch_name` fixture to `tests/conftest.py` that reads
  `request.module.BRANCH` when the module defines one (files keep their own
  `BRANCH` constants — many tests reference the branch name in path assertions).
- Add a base `project` fixture that does
  `ensure_branch_layout(tmp_path, branch_name)` and returns `tmp_path`.
- Add a `project_with_run` variant that also calls `set_current_run`
  (needed by `test_harness.py` and the split ticket test files).
- Remove the per-file fixture copies from the 7 duplicating files.
- The class-level `project` override in `TestMentionBumpAutoTurns`
  (`test_tui.py`) stays as-is — it does `ensure_base_layout` +
  `ensure_branch_layout` + `set_current_run`, which is genuinely different.
- Also lift `setup_project()` / `CliRunner()` boilerplate from CLI test files
  into shared fixtures if it helps the subsequent split.

Run full test suite. Commit.

### Phase 2: Split `test_cli_ticket.py`

The file is 3,194 lines with 32 test classes. Split into:

| New file | Classes |
|---|---|
| `test_cli_ticket_lifecycle.py` | `TestTicketCreate`, `TestTicketCreateOptions`, `TestTicketCloseArchive`, `TestTicketCloseIdempotent`, `TestTicketCloseReason`, `TestTicketCloseDuplicate`, `TestTicketCloseDuplicateValidation`, `TestTicketCloseUnblocked`, `TestTicketClosed`, `TestTicketDelete`, `TestTicketMove`, `TestTicketPull`, `TestTicketAddNote` |
| `test_cli_ticket_list.py` | `TestTicketList`, `TestTicketListClosedCount`, `TestTicketListPriority`, `TestTicketListTable`, `TestTicketListJson`, `TestTicketListFilters`, `TestTicketListDepsJson`, `TestNoResultsMessages`, `TestFormatTicketLine`, `TestFormatTicketSummary` |
| `test_cli_ticket_show.py` | `TestTicketShow`, `TestTicketShowRelationships` |
| `test_cli_ticket_deps.py` | `TestTicketDep`, `TestTicketUndep`, `TestTicketDepTree`, `TestTicketDepCycle`, `TestTicketBlocked` |
| `test_cli_ticket_links.py` | `TestTicketLink` |
| `test_cli_ticket_worklog.py` | `TestTicketLog` |

Keep `test_cli_ticket.py` deleted (no stub). Use shared fixtures by default;
keep explicit inline setup only where the test is verifying alternative
branch/run state (e.g., `test_move_no_active_branch_errors`, done-branch
dependency/list cases).

Run full test suite. Commit.

### Phase 3: Import sweep

Update test files to import from the specific CLI submodules
(`kingdom.cli.ticket`, `kingdom.cli.council`, `kingdom.cli.peasant`, etc.)
instead of `from kingdom.cli import ...` or `from kingdom import cli`.

Keep one thin smoke test around `kingdom.cli.__init__` so the top-level wiring
still gets coverage (Codex's suggestion — good catch).

Run full test suite. Commit.
