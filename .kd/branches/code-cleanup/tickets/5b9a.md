# Humanize kd peasant watch output — translate internals to user language

The watch output still exposes implementation internals instead of telling the King what's happening. Specific issues from real peasant run on 7868:

1. 'worktree: M src/foo.py' — 'worktree:' is developer language, 'M' is a git status flag. Should say 'Editing src/foo.py' or 'Created tests/bar.py'.
2. '(committed)' — guesses a commit happened from dirty→clean transition without verifying. Should run 'git log -1 --oneline', compare HEAD SHA, and show the actual commit: 'Committed abc1234 "Auto-create thread when none exist"'.
3. '(2m since last entry)' — reads like a hang warning, not progress. Drop it entirely; the timestamp already gives timing.
4. 's' eaten from 'src/' — real rendering bug, 'M rc/kingdom/cli/council.py' appeared in terminal. Investigate whether Rich or terminal wrapping is responsible.
5. Lines are too short. This is a coding-agent transcript, not a status bar. Let entries breathe.

Related: 8364 covers the timestamp mismatch separately. Council summary quality (skip opener fluff) is covered by backlog ticket 2f13 (cheap LLM summarizer).

## Implementation Notes

### The rendering bug
`highlight=False` only disables Rich's automatic highlighting (numbers, URLs). It does NOT disable markup parsing. So `[09:10]` in `f"  [{ts}] Editing src/..."` is parsed as a Rich style tag. `[s]` from the start of `src/` is also parsed as markup, which silently eats the `s` — producing `rc/kingdom/...` in the terminal.

The worklog lines at line 617 correctly use `markup=False`. The worktree/commit lines at 657, 667-668, and 671 use `highlight=False` instead. Fix: change all three to `markup=False`.

Three lines to change in `src/kingdom/cli/peasant.py`:
- Line 657: `console.print(f"  [{ts}] {entry}", highlight=False)` → `markup=False`
- Line 666-668: `console.print(f'  [{ts}] Committed ...', highlight=False)` → `markup=False`
- Line 671: `console.print(f"  [{ts}] Changes cleared", highlight=False)` → `markup=False`
