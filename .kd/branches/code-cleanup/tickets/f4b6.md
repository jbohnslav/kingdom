# Remove backend timeout from peasant harness

## Problem

The harness kills the backend agent after 900s (15 minutes) and fails the
entire session. This is solving an imaginary problem ("what if the process
hangs forever?") while creating a real one ("my peasant keeps dying mid-task").

Agents doing real work routinely need 20-30+ minutes. The timeout kills them
for being productive.

## Why a timeout is unnecessary

The real safety nets already exist:
- `kd peasant stop` lets the King kill a stuck peasant manually
- The 50-iteration loop caps total work
- `stop_requested` handles Ctrl+C/SIGTERM from the King or the system

If the agent is genuinely stuck, the King notices and intervenes. That's the
workflow. An auto-timeout adds complexity (retry logic, resume recovery,
consecutive timeout tracking) to solve a problem that doesn't happen in practice.

## Fix

Remove the `timeout` parameter from `run_streaming_subprocess()` and the
`agent_timeout` plumbing in `run_agent_loop()`. Let `proc.wait()` block
indefinitely. The existing `stop_requested` signal handler and `kd peasant stop`
are sufficient for killing stuck agents.

Also remove the `agent_timeout` config field from `PeasantConfig` if it exists,
and the `--timeout` flag from any CLI commands that pass it through.
