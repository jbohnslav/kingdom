# Peasant harness should resume after backend timeout, not fail

When the backend times out (subprocess.TimeoutExpired at harness.py:943), the harness sets final_status='failed' and breaks out of the loop. This kills the entire session even though the agent may have done useful work (commits, file changes) that persists in the worktree.

The harness has 50 iterations available. A timeout should mean 'this call ran too long — resume on the next iteration,' not 'give up entirely.' The agent's resume_id mechanism exists precisely for this.

## Root Cause

harness.py:943-947:
```python
except subprocess.TimeoutExpired:
    logger.error('Backend timed out after %ds', agent_timeout)
    append_worklog(ticket_path, 'Backend call timed out')
    final_status = 'failed'
    break
```

## Fix

Two changes:

### 1. Increase default agent timeout to 1800s (30 minutes)

The current 900s (15min) default is too short for large tasks. Agents doing
real work (splitting files, running full test suites, sweeping imports) routinely
need 20-25 minutes. Bump the default to 1800s. This is the `agent_timeout`
parameter in `run_agent_loop()`.

### 2. Resume after timeout instead of failing

On timeout:
1. Log the timeout to the worklog (already done)
2. Do NOT break — continue to the next iteration
3. Attempt to recover a resume_id from any partial output (the streaming log may have captured enough)
4. If no resume_id, start a fresh agent call — the prompt includes the worklog, so the agent picks up context from what it already logged
5. Decrement remaining iterations as normal

The only case where a timeout should be fatal is if the agent has timed out on every iteration (stuck in a loop). Consider failing after N consecutive timeouts (e.g. 3) rather than on the first one.

## Acceptance Criteria

- [ ] Default agent timeout increased to 1800s (30 minutes)
- [ ] Backend timeout does not kill the session — harness continues to next iteration
- [ ] Timeout is logged to worklog (already works)
- [ ] Resume ID is recovered from partial output when possible
- [ ] Session fails after N consecutive timeouts (e.g. 3), not on first timeout
- [ ] Agent picks up context from worklog on fresh start after timeout
- [ ] Tests: timeout triggers retry, N consecutive timeouts trigger failure
