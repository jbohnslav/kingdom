# Peasant agent escapes worktree and commits to wrong branch

## The Problem

In the 8364 run, the peasant agent was launched with `cwd=.kd/worktrees/8364` (on branch `ticket/8364`), but navigated to the main repo at `/Users/jrb/code/kingdom` and committed `1e29a7d` to `code-cleanup` instead. The harness correctly rejected the DONE claim (no changes in the worktree), but the rogue commit was already on the King's working branch. This wasted 7 minutes and polluted `code-cleanup`.

There are **zero guardrails** preventing this:

1. **No prompt boundary.** The system prompt in `build_prompt()` (`harness.py:33-86`) never mentions the worktree path, the ticket branch name, or that the agent should stay in its working directory.
2. **No runtime detection.** Nothing checks whether the agent `cd`'d out of the worktree during execution.
3. **No post-execution branch validation.** `has_code_changes()` (`harness.py:285-316`) checks the worktree for changes but doesn't verify commits are on the correct branch (`ticket/{id}`).
4. **No worktree-specific CLAUDE.md.** The worktree's `CLAUDE.md` is identical to the root — no isolation instructions.

## Root Cause

The agent sees file paths like `src/kingdom/harness.py` and resolves them against the filesystem. If it runs `git rev-parse --show-toplevel` or just navigates up, it finds `/Users/jrb/code/kingdom` (the main repo) and starts working there instead of `.kd/worktrees/8364`. Nothing in the prompt anchors it.

## Proposed Fix (defense in depth)

### Layer 1: Prompt anchoring (prevent)
- In `build_prompt()`, explicitly state:
  - The worktree path the agent is in
  - The branch it should be on (`ticket/{id}`)
  - That it must NOT cd out of the worktree or commit to any other branch
  - All file paths are relative to the worktree

### Layer 2: Post-iteration branch validation (detect)
- After each agent call returns, verify:
  - `git rev-parse --abbrev-ref HEAD` in the worktree still equals `ticket/{id}`
  - `git rev-parse --show-toplevel` still equals the worktree path
- If the branch changed, log a loud warning and reject the iteration

### Layer 3: Post-execution audit (catch)
- Before accepting DONE, extend `has_code_changes()` to also check:
  - All new commits since `start_sha` are on `ticket/{id}`, not the feature branch
  - The main repo (`base`) has no new commits that weren't there at session start
- If rogue commits are detected, warn the King and reject DONE

### Layer 4: Worktree CLAUDE.md (reinforce)
- When creating a worktree, write a worktree-specific CLAUDE.md that includes:
  - "You are working in an isolated worktree at {path}"
  - "Your branch is ticket/{id} — do not checkout or commit to any other branch"
  - "All file paths should be relative to this directory"

## Acceptance Criteria

- [ ] System prompt tells the agent its worktree path and branch name
- [ ] System prompt explicitly says to stay in the worktree
- [ ] After each iteration, harness validates the worktree branch hasn't changed
- [ ] Branch escape triggers a loud warning in the worklog and rejects the iteration
- [ ] `has_code_changes()` validates commits are on the ticket branch
- [ ] Rogue commits on the feature branch are detected and flagged
- [ ] Worktree CLAUDE.md includes isolation instructions
- [ ] Test: agent that escapes worktree is detected and rejected
