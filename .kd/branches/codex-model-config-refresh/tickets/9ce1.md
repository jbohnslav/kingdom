# Refresh council and worker model defaults for current Claude, Cursor, and Codex models

## Description

Refresh Kingdom's model configuration surface for the July 2026 model lineup
without putting the project on a model-name treadmill. The current zero-config
behavior delegates model selection to the provider CLIs, but the dogfood config
pins Codex to `gpt-5.4`, the docs repeat that stale pin, and Kingdom only models
Codex reasoning effort at `low|medium|high`.

Keep model catalogs provider-owned and account-aware. Kingdom should express
role intent (agent, model override when desired, and effort), validate what each
backend can represent, and record what actually ran.

## Acceptance Criteria

- [x] Decide and document the pinning policy: built-in defaults inherit provider CLI defaults; explicit model IDs remain an opt-in reproducibility tool.
- [x] Keep the zero-config council portable and diverse (`claude` + `codex`); document Cursor as an opt-in member rather than a required third CLI.
- [x] Replace or deprecate Codex-only `reasoning_effort` with a backend-aware effort setting that maps to Claude `--effort` and Codex `model_reasoning_effort`.
- [x] Support the effort levels exposed by current CLIs (`xhigh`, `max`, and Codex `ultra` where the selected model supports it) without claiming Cursor has a separate effort flag.
- [x] Record runtime backend, model/effort selection and source, and CLI version in council/review thread messages; use `unknown` when a provider does not expose the effective value.
- [x] Make `kd doctor` distinguish inherited vs pinned model selection and report model/access incompatibilities clearly.
- [x] Add role-oriented examples for council/review, peasant, and lord agents, including economical worker models and stronger supervisor/reviewer models.
- [x] Update `docs/config.md`: remove stale `gpt-5.4` guidance and make the full example valid (nested `council.ask`/`council.chat`, no unsupported `peasant.timeout`, and document `lord`).
- [x] Update relevant config, command-builder, doctor, and documentation tests; run the full test suite.
