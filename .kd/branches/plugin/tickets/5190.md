# Peasant reject/stop lifecycle: reject doesn't kill process, status shows stale runs

When rejecting a peasant with --no-resume, the process keeps running and status shows it as 'working'. stop fails with 'No PID found'. The reject/stop lifecycle is broken — ticket state changes but runtime state is left dangling.

## Acceptance Criteria

- [ ] - [ ] reject (with or without --no-resume) kills the peasant process if PID exists
- [ ] reject marks the peasant run as closed even if PID is missing (no stale 'working' entries)
- [ ] kd peasant status auto-prunes or flags stale entries (missing PID, no heartbeat)
- [ ] kd peasant stop works when PID tracking is out of sync (force-close fallback)
- [ ] Add manual cleanup command for orphaned peasant runs
- [ ] Triggered by real workflow: peasant implemented wrong spec, needed hard rejection, couldn't cleanly terminate
