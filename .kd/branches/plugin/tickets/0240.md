# Stop blocker: skip block when no active ticket

The Stop hook blocks on had_work && \!did_log regardless of whether there's an active ticket. Version bumps, typo fixes, and other ticketless chores trigger a block with no ticket to log against. Fix: check kd tk current --id at Stop time, only block when an active ticket exists.

Scope update (2026-03-05): move canonical hook source out of `.claude/` into tracked project code so peasant worktrees can edit it. Runtime install/sync is tracked in linked ticket `d1fa`.

## Acceptance Criteria

- [ ] Stop handler runs `kd tk current --id` with a short timeout before any block decision
- [ ] If `kd tk current --id` fails or times out, Stop fails open (no block)
- [ ] No active ticket + `had_work` + `!did_log` passes through (no block)
- [ ] Active ticket + `had_work` + `!did_log` blocks, and reason includes a concrete command with the real ticket id (`kd tk log <id> "..."`) and no placeholder token
- [ ] Canonical hook script source is moved to tracked project code (not `.claude/`) so peasant worktrees can edit it reliably (implementation via linked `d1fa`)
- [ ] Tests cover:
- [ ] no active ticket + had work => no block
- [ ] active ticket + had work + no log => block
- [ ] ticket created/accepted mid-turn => Stop resolves current ticket at Stop-time and enforces correctly
