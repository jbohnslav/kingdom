# Cross-branch workflow: peasant accept and tk move should work across sessions

When switching branches frequently, several cross-branch operations are painful:

1. **kd peasant accept fails across branches**: Started a peasant on branch A, switched to branch B with kd start --force, then couldn't accept the peasant's work because it was tied to the old session. peasant accept should work regardless of which session is currently active.

2. **kd tk move can't move across branches**: Tickets can only move within a branch or to/from backlog. There's no way to move a ticket from one branch to another without manually moving files. kd tk move should support --from <branch> or similar to move tickets between branches.

3. **General friction**: The session model assumes you stay on one branch. When you context-switch (common in real work), you hit walls. The workaround is manually moving .kd ticket files, which defeats the purpose of the CLI.

4. **No branch switch command**: `kd start --force` is the only way to change the active session, but it's designed for init, not switching. A dedicated `kd switch <branch>` command would make context-switching a first-class operation — validate the branch exists in .kd/branches/, update .kd/current, and print a summary of the target branch's state.

Merged 9728 (kd switch command) into this ticket.

## Design (council-approved)

### kd switch
- Pure kd session concept — updates `.kd/current`, no git interaction
- `kd switch <branch>`: validate branch exists in `.kd/branches/`, update `.kd/current`, print summary (open tickets, status, current git branch for context)
- `kd switch` (no args): list tracked branches, mark current kd session and current git branch separately so mismatches are visible
- Does not require git HEAD to match — the whole point is managing branch Y while on git branch X

### peasant accept (and other post-start commands)
- Root cause: `resolve_peasant_context()` in `peasant.py:62` forces lookup through `resolve_current_run()`, scoping to the active session
- Fix: find the peasant's owning branch by scanning `.kd/branches/*/sessions/peasant-<id>.json` across all branches
- Keep the git HEAD gate for merge safety — but make error actionable: "Run `git checkout <branch>` first"
- Audit all peasant post-start commands (accept, reject, review, read, watch) — they all call `resolve_peasant_context()` and have the same bug

### tk move between branches
- Syntax: `kd tk move <id> --to <branch>` — search all branches for source ticket (IDs are globally unique)
- Skip `--from` flag — YAGNI until ID collisions actually happen. If ambiguous, error with "found in multiple locations, specify --from"
- Validate `--to` target exists in `.kd/branches/` — no silent directory creation
- Block moves on tickets with active peasants (status in_progress/in_review with a peasant session) — session state still points to old branch

### Footguns to guard against
- All peasant post-start commands use `resolve_current_run()` — must be audited and fixed, not just accept
- Worktree registry in `state.json` tracks peasant worktrees per-branch — moving a ticket orphans that entry
- `kd switch` should always show both kd session and git branch to surface mismatches

## Acceptance Criteria

- [ ] `kd switch <branch>` updates `.kd/current`, prints branch summary with ticket counts and git branch context
- [ ] `kd switch` (no args) lists tracked branches with current markers
- [ ] `kd peasant accept` works when active session differs from peasant's owning branch
- [ ] All peasant post-start commands (accept, reject, review, read, watch) resolve by peasant ownership, not current session
- [ ] Git HEAD gate preserved for merge safety — actionable error message when on wrong branch
- [ ] `kd tk move <id> --to <branch>` searches all branches for source ticket
- [ ] `--to` validates target exists in `.kd/branches/` — no silent dir creation
- [ ] `tk move` blocked for tickets with active peasant sessions
- [ ] No manual file moves needed for common cross-branch workflows
