# Council: surface writable/read-only mode status to agents

During the d4fc council session, agents repeatedly described changes instead of making them because they couldn't tell they were in read-only mode. When the King says '@agent do it' and the agent can't write, the agent should say so immediately — but agents need to know their mode to do that. Add a clear mode indicator (writable vs read-only) visible to council participants at session start or on first write attempt, so agents stop producing descriptions when the King expects execution.

## Acceptance Criteria

- [ ] Council agents can detect whether they have file-write permissions
- [ ] If in read-only mode and asked to edit, agent's first line states it cannot edit in current mode
- [ ] Mode status is surfaced without requiring a failed tool call to discover it
