# Shift+Enter should insert a newline in the chat TUI input

## Acceptance Criteria

- [x] Pressing Shift+Enter inserts a newline at the cursor position in the chat input
- [x] Pressing Enter without Shift submits the message as before
- [x] Multi-line messages created with Shift+Enter are sent with preserved line breaks
- [x] Input behavior is covered by TUI tests for both submit and newline paths

## Worklog

- Root cause: TextArea only maps `"enter"` → `"\n"`, not `"shift+enter"`. The old guard `"shift" not in event.key` was effectively dead code since `event.key == "shift+enter"` already fails the `== "enter"` check.
- Fix: explicit `"shift+enter"` handler in `handle_key()` that calls `_replace_via_keyboard("\n", start, end)`
- Updated test from checking "no Submit" to verifying newline is actually inserted
