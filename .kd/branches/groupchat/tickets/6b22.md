# Bug: kd chat <thread-id> ignores the argument and always shows the newest thread

## Description

`kd chat <thread-id>` should open the requested thread deterministically. Current behavior can ignore the explicit argument and land on a different thread, which breaks resume workflows.

## Acceptance Criteria

- [x] `kd chat <thread-id>` resolves the explicit thread id first (exact id or unique prefix)
- [x] Explicit thread argument takes precedence over `current_thread` and "most recent thread" fallback behavior
- [x] Ambiguous prefixes return a clear error listing matching thread ids
- [x] Unknown thread ids return a clear not-found error
- [x] When a thread is resolved explicitly, chat opens on that thread and updates `current_thread`
- [x] CLI tests cover exact match, unique prefix, ambiguous prefix, and not-found cases
