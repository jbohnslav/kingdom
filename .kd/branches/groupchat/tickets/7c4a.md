# Bug: CLI error messages print twice (print_error + typer echo duplication)

## Description

Many CLI commands use `print_error("message")` followed by `raise typer.Exit(code=1)`. The error message appears twice in the terminal — once from `print_error` (Rich console to stderr) and once from Typer's error output. Reproduced with `kd tk link aaaa` and `kd tk link A A`.

Pre-existing issue across the codebase, not specific to any one command.

## Acceptance Criteria

- [x] Error messages display exactly once
- [x] Consistent pattern for error handling across all commands

## Worklog

- Root cause: error messages used `typer.echo` (stdout) + `raise typer.Exit(1)`, mixing with `print_error` (stderr). In some terminal setups, stdout+stderr interleaving made messages appear doubled.
- Converted 71 `typer.echo` + `raise typer.Exit(code=1)` patterns to `print_error` + `raise typer.Exit(code=1)`
- Multi-line error blocks: leading error via `print_error()`, supplementary detail lines via `error_console.print()` (stderr, no "Error:" prefix)
- All error exits now consistently go to stderr via Rich console
