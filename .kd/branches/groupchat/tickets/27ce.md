# Phase 3: group chat auto-mode orchestration (round-robin, interrupts, stop conditions)

## Description

After dogfooding `kd chat` (Phase 2), build the chat auto-mode orchestration layer with explicit round semantics, deterministic interrupt handling, and nested chat config wiring.

Deferred from council-improvements PR intentionally. Design doc captures full requirements under Phase 3. Ticket this when Phase 2 is stable and dogfooded.

## Acceptance Criteria

- [x] Chat orchestration reads `council.chat.mode` and `council.chat.auto_rounds` (not legacy flat keys)
- [x] A round is defined as one full pass over eligible (non-muted) members
- [x] `natural` mode: first turn is parallel broadcast, then shuffled round-robin for `auto_rounds` rounds (shuffle deferred to 7afc)
- [x] `round_robin` mode: no initial broadcast; fixed-order sequential turns for `auto_rounds` rounds (mode definitions deferred to 7afc)
- [x] Thread history injection: each auto-turn builds full thread context into the prompt (already done via `format_thread_history`)
- [x] User typing interrupts auto-mode: stops scheduling new turns, current generation completes, user message sent after
- [x] Stop condition: max rounds reached (hard cap, no heuristics)
