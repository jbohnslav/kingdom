# Fix kd root discovery: find_project_root() replaces Path.cwd()

Add a shared `find_project_root()` helper and replace `.kd`-state-resolution call sites in cli.py that currently use `Path.cwd()`.

**Scope:** Only replace `base = Path.cwd()` calls that locate `.kd` project state. Do NOT touch call sites where `cwd` is used for other semantics.

Resolution order:
1. `KD_BASE` env var (explicit override for agents/CI) — if set but path is invalid or missing `.kd/`, fail loudly with the bad path in the error; never silently fall through
2. cwd (if `.kd/` exists here, fast path)
3. Walk parent directories (handles agent cd'd into subdirs)
4. `git rev-parse --show-toplevel` (belt-and-suspenders fallback)
5. Error with clear hint to run `kd init`

Exceptions — these stay anchored to `Path.cwd()`:
- `kd init` — user is explicitly choosing where to create `.kd/`
- `kd work` worktree default (cli.py ~line 2855) — cwd is the intended interactive worktree, not project root
- `setup-skill` path discovery (cli.py ~line 206) — not `.kd` state resolution; out of scope unless intentionally redesigning

Tests needed:
- `kd tk list` from a subdirectory finds `.kd/` at repo root
- `KD_BASE` env var overrides all other discovery
- `KD_BASE` set to invalid path produces explicit error (includes the bad path)
- `kd init` ignores discovery and uses cwd
- `kd work` default worktree stays cwd (regression)
- Missing `.kd/` everywhere produces clear error message
