# Update README and workflow scale docs to show kd supports lightweight usage patterns

## Context

Not every feature of kd needs to be used on every branch. The README and workflow scale docs should make it clear that kd supports a spectrum of usage patterns, from heavyweight to lightweight:

**Full workflow** (new features): design → breakdown → tickets → council → peasants → review → merge

**Medium workflow** (smaller features/refactors): pull tickets into a branch, work them (with or without peasants), review and merge — no design phase needed.

**Lightweight workflow** (bug fixes): work a single ticket on a branch, close it, make a PR. Or batch several bug-fix tickets on one branch without any design phase.

The key message: kd scales down gracefully. You pick the parts of the workflow that fit the size of the work.

## Acceptance Criteria

- [ ] README updated to show multiple usage patterns / workflow scales
- [ ] Workflow scale documentation updated with examples of lightweight usage
- [ ] Clear that design/council/peasants are optional — not every branch needs them
