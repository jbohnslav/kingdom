# Lord worklog hygiene: epic worklog as decision history, not transcript

The lord logs to the epic worklog every cycle, even idle ones. Result: verbose repetitive entries ("still awaiting_council, nothing to do") that drown out real progress. The epic worklog should be durable decision history, not a live transcript.

## Design (council-confirmed)

**Log only durable events:**
- Peasant launches
- Accepts / rejects with rationale
- Council bounces
- Escalations to the King
- Merge conflict resolutions
- Blocked states
- Epic completion
- Stop/start lifecycle events

**Keep verbose per-cycle narration in `agent-live.log`**, not the ticket worklog.

**Implementation:** One prompt line in the lord system prompt telling it when to log. Combined with 2ca9 (idle detection), most idle cycles won't reach the agent anyway — this handles the remaining edge cases.

**Note:** Depends on 2ca9. After implementing idle detection, re-run the lord and verify whether worklog noise is still a problem before adding guardrails. The prompt tweak may be unnecessary if idle cycles are eliminated.

## Acceptance Criteria

- [ ] Lord prompt instructs agent to only log on durable state changes (not idle observations)
- [ ] Epic worklog contains only actionable entries after a full lord run
- [ ] Per-cycle narration preserved in agent-live.log for debugging
