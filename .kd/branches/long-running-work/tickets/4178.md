# Lord mode: autonomous supervisor agent for managing peasant workflows

An LLM agent that manages the full peasant inner loop: start peasants on ready tickets, monitor progress, review completed work, accept/reject, resolve merge conflicts, and start the next wave as tickets unblock. Replaces the King's manual poll-and-accept workflow.

The lord is CLI-driven — it calls `kd` commands, not Python internals. It runs in the base checkout on the feature branch. Any agent backend can be a lord.

See design doc for full architecture (lord loop diagram, merge conflict flow, epic worklog pattern, review approach).

## Design Decisions

- **Agent, not deterministic** — merge conflicts, review judgment, and escalation need LLM reasoning
- **Standalone `lord_loop()`** — not the peasant harness (too coupled to code-editing workflows)
- **Poll loop with interruptible sleep** — default 5-minute interval
- **`kd lord stop` via session status** — sets status to "stopping", lord checks each cycle
- **One lord per branch** — session name `lord-<branch>`
- **Epic worklog for cross-ticket state** — lord logs progress, conflicts, decisions to epic ticket
- **Failed peasant → mark blocked, continue** — stop only when no runnable work remains

## Acceptance Criteria

- [ ] `kd lord start [<epic-id> | --all]` launches a supervisor agent session
- [ ] Lord polls `kd tk list --ready --json` and starts peasants on startable tickets
- [ ] Lord polls `kd peasant status --json` and detects completed/failed peasants
- [ ] Lord reviews completed work via `kd peasant review` and accepts or rejects with reasoning
- [ ] Lord resolves merge conflicts on accept (same flow as a human — resolve in worktree, retry)
- [ ] Lord escalates complex merge conflicts and ambiguous reviews to the King (stops and reports)
- [ ] Lord starts next wave of peasants as tickets unblock from dependency closures
- [ ] Lord logs cross-ticket progress to epic worklog (if managing an epic)
- [ ] Lord marks persistently-failing tickets as blocked and continues with remaining work
- [ ] `kd lord stop` signals graceful shutdown — lord finishes current cycle and exits
- [ ] `kd lord status` shows lord activity, managed tickets, active peasants, and progress
- [ ] `kd lord log` shows lord's worklog and decisions
- [ ] Configurable: `--interval`, `--review-depth`, `--max-peasants`, `--max-runtime`
