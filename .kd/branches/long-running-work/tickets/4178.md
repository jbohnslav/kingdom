# Lord mode: autonomous supervisor agent for managing peasant workflows

An LLM agent (the "lord") that manages the full peasant lifecycle for an epic: start peasants on ready tickets, monitor progress, review completed work at the cross-ticket integration level, accept/reject with feedback, resolve merge conflicts, and start the next wave as tickets unblock. One lord per epic.

The lord is CLI-driven — it calls `kd` commands, not Python internals. It runs in the base checkout on the feature branch. The lord is the most capable model available (Opus-tier) so it can handle conflict resolution and cross-ticket review autonomously.

## Design Decisions

- **Agent, not deterministic** — merge conflicts, review judgment, and escalation need LLM reasoning
- **One lord per epic** — scoped to an epic's children via the existing `parent` field
- **Toolkit, not rigid loop** — lord has available actions (check status, start peasant, accept/reject, resolve conflicts, escalate, sleep) and makes its own sequencing decisions
- **Cross-ticket integration review** — the lord's unique value-add over peasant self-review; checks whether individually-correct tickets compose cleanly
- **Requeue with feedback** — rejection means retry with specific guidance, not immediate escalation; escalate after 2-3 bounces on the same issue
- **Merge conflict resolution is required** — lord resolves conflicts itself, only escalates truly ambiguous semantic conflicts
- **Default ~10 parallel peasants** — the whole point is massive parallelism
- **Epic worklog for cross-ticket state** — lord logs progress, conflicts, decisions to epic ticket
- **No automatic `kd done`** — lord declares "epic complete" and stops; branch archiving is the King's call
