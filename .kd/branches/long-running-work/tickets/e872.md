# peasant watch doesn't show council query activity

`kd peasant watch` shows "Still working... Xm since last activity" while a peasant is waiting on council responses. The peasant logs show council queries were dispatched, but watch doesn't surface this.

`thread_response_status()` in `thread.py` already detects active council queries by checking for `.stream-*.jsonl` files and tracking which members have responded. Wire this detection into the watch heartbeat/poll.

## Acceptance Criteria

- [ ] Watch detects active council queries (via stream files in the work thread directory)
- [ ] Watch displays council status instead of "Still working" (e.g. "Awaiting council response — claude responded, codex pending")
- [ ] Watch resumes normal "Still working" heartbeat after council query completes
- [ ] No false positives when stream files don't exist
