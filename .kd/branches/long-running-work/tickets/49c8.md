# Branch name slugification breaks peasant accept for slash-prefixed branches

`kd peasant accept` fails for branches with slashes (e.g. `jrobinsonbohnslav/sft-input-processor-protocol`).

## Root Cause (council-confirmed)

Two bugs working together:

**Bug A — error message lies about what's compared.** Line 1490 compares `normalize_branch_name(feature)` but the error message displays `git_branch_name` (from state.json). These are different values. `feature` is the `.kd/branches/` directory name (already normalized), while `git_branch_name` is the original git ref from state.json. When the user fixed state.json, the error showed two matching strings, but the gate still failed because it compared the invisible `feature` value.

**Bug B — merge-safety check uses normalized names instead of git refs.** The check exists to prevent merging onto the wrong branch. Comparing `normalize_branch_name(current_branch) != normalize_branch_name(feature)` is wrong because normalization is lossy (slashes → dashes). The check should compare original git branch names: `current_branch` (from git) vs `state.json["branch"]` (stored original).

## The Fix

Replace `peasant.py:1490`:
```python
# Before (broken): compares normalized dir names, displays git refs
if normalize_branch_name(current_branch) != normalize_branch_name(feature):
    print_error(f"Cannot accept: expected to be on '{git_branch_name}' ...")

# After: compare original git refs directly
if current_branch != git_branch_name:
    print_error(f"Cannot accept: expected to be on '{git_branch_name}' but HEAD is on '{current_branch}'.")
```

Also show the internal `feature` (directory key) in the error for debugging when values diverge.

- [ ] Merge-safety check compares original git branch names, not normalized directory keys
