# Support Codex reasoning effort in kd config

Add first-class config support for Codex reasoning effort so kd can express settings like low/medium/high without encoding effort into the model name. Current failure mode: .kd/config.json set codex model to gpt-5.4-high, which is rejected for ChatGPT-backed Codex accounts, while gpt-5.4 works when paired with model_reasoning_effort set separately.

Decisions:
- `reasoning_effort` should be a first-class field on `agents.<name>`, separate from `model`.
- `reasoning_effort` should be supported for the `codex` backend and translated by the Codex command builder to the correct CLI/config setting.
- Setting `reasoning_effort` on unsupported backends should be an invalid config surfaced by validation and `kd doctor`.
- Different effort levels for council vs peasant should be configured via different named agents, reusing existing `council.members` and `peasant.agent` selection points rather than adding a new per-context override system in v1.

## Acceptance Criteria

- [ ] `kd` config supports `agents.<name>.reasoning_effort` with validated values for the Codex backend.
- [ ] Codex command building passes `reasoning_effort` through using the correct Codex config mechanism while keeping `model` separate.
- [ ] Using `reasoning_effort` on unsupported backends fails config validation and is reported by `kd doctor`.
- [ ] Existing configs without `reasoning_effort` continue to behave the same as before.
- [ ] Tests cover config validation, command building, and the invalid-backend case.
- [ ] Documentation or examples show the intended pattern for separate council and peasant agent names when different effort levels are needed.
