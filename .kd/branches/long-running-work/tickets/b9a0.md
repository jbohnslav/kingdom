# Lord agent: epic-scoped supervisor with toolkit and prompt

The core lord agent. An LLM session (Opus-tier) scoped to one epic's children. The lord gets a system prompt and a toolkit of kd commands: peasant start/status/accept/reject, tk list/show/log, plus direct file access for conflict resolution and cross-ticket integration review. Key behaviors: (1) Discover startable tickets in the epic (children that are open/ready and not already assigned to a peasant). (2) Start up to ~10 peasants in parallel. (3) Monitor peasant completions via kd peasant status --json. (4) Review completed work at the cross-ticket level — not redoing peasant review, but checking whether tickets compose cleanly. (5) Accept or reject with feedback; requeue on rejection with specific guidance, escalate after 2-3 bounces. (6) Resolve merge conflicts directly in the worktree. (7) Log all decisions to the epic worklog. (8) Declare epic complete when all children are closed, then exit. (9) Check for stopping status each cycle for graceful shutdown.

## Acceptance Criteria

- [ ] kd lord start <epic-id> launches a Claude session scoped to the epic
- [ ] Lord discovers and starts peasants on startable epic children
- [ ] Lord detects completed peasants and performs cross-ticket integration review
- [ ] Lord accepts or rejects with feedback; requeues with guidance before escalating
- [ ] Lord resolves merge conflicts in the worktree
- [ ] Lord logs decisions to epic worklog
- [ ] Lord exits when all epic children are closed or when stop is signaled
- [ ] Lord escalates to the King after 2-3 failed requeue attempts on the same ticket
