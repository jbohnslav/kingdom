# PR #37 re-review: lord config, drain perf, escalation tracking

PR #37 re-review surfaced new issues after the livelock/cycle-counting fixes landed.

## 1. Add LordConfig with independent agent selection (MEDIUM)
Lord defaults to cfg.peasant.agent — no way to configure a different model for the lord without passing --agent every time. Council reviewed (council-cfaf), unanimous on design:

Add top-level `lord` section parallel to `peasant`:
```json
{
  "lord": { "agent": "claude", "max_cycles": 200 },
  "peasant": { "agent": "codex" },
  "council": { "members": ["claude", "codex"] },
  "agents": { ... }
}
```

Implementation:
```python
@dataclass
class LordConfig:
    agent: str = ""      # falls back to peasant.agent if unset
    max_cycles: int = 200
```

- `lord.agent` optional, falls back to `peasant.agent` (preserves existing configs)
- Resolve fallback in `validate_config`, not scattered across call sites
- Add `max_cycles` (LLM budget) — users need to tune per epic size/cost
- Leave `max_iterations` as a hardcoded safety net (not user-tunable)
- Leave backoff params, `MAX_REQUEUE_ATTEMPTS`, `MAX_PARALLEL_PEASANTS` as constants
- No model-tier enforcement in schema — guidance in docs/examples only
- Update `kd lord start` to read `cfg.lord.agent`

## 2. drain opens file per-line (MEDIUM)
lord_harness.py drain() opens and closes agent-live.log for every single line of subprocess output — thousands of open/close syscalls per LLM response. Should open once outside the loop.

## 3. ESCALATE status overwritten by subsequent DONE (LOW)
When lord escalates a ticket, final_status is set to "blocked". If remaining tickets close, final_status becomes "done" and escalation is silently forgotten. Track escalations separately.

## 4. filter_worklog_lines uses startswith("lord") not "lord-" (LOW)
Imprecise match — a future author like "lordship" would be included. Use startswith("lord-").

## 5. list_tickets called repeatedly for dep status map (LOW)
get_startable_children and get_children_summary both call list_tickets(tickets_dir) per invocation. Already cached children/tickets per cycle but the full-branch status_by_id map is not cached.

## 6. os.killpg assumes PID==PGID (NEGLIGIBLE)
Works because start_new_session=True but assumption is implicit. Add comment or store PGID explicitly.
