# Tune council review timeout and prompt cost

Council review on peasant work is timing out too often with the current setup. We want to raise the review timeout and make the review prompt cheaper so reviewers do not default to rerunning the full test suite, while keeping the current escalation policy where reviewer timeout/error still escalates to the king. Acceptance direction: increase the configured timeout, update review prompt guidance to rely on peasant verification by default and only rerun targeted checks when needed, and add/update tests accordingly.

## Worklog

- 2026-03-06 10:03 — Context gathered: project config still sets council.timeout=600, and the shared build_review_prompt() currently tells reviewers to 'Run the project's test suite and linter to verify.' That guidance is too expensive for slow review models and is likely contributing to peasant council timeouts. Planned change: raise the configured timeout and rewrite the review standard so reviewers rely on peasant verification by default, inspect code first, and only rerun targeted checks when needed.

Added a prompt regression test in tests/test_harness.py.
