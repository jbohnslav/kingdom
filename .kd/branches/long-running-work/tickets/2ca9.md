# Lord idle detection: harness-side pre-check with backoff

The lord harness calls the LLM every ~5 seconds regardless of whether anything changed. In our first real run (3 tickets, 26 cycles), 10+ cycles were pure idle — the agent just said "still waiting, nothing to do" and burned tokens.

## Design (council-confirmed)

Move idle detection into the harness. Before calling the LLM, snapshot peasant/ticket state and compare to last seen. If nothing changed, sleep with backoff — don't call the agent at all.

**Harness pre-check (pseudocode):**
```python
current_states = get_children_summary(epic_id)
if current_states == last_seen_states:
    sleep(backoff_delay)  # 5s -> 15s -> 30s -> 60s cap
    continue  # skip LLM call entirely
else:
    last_seen_states = current_states
    backoff_delay = 5  # reset on change
```

**"Actionable" means at least one of:**
- A startable child exists (open, no blocking deps)
- A peasant is `needs_king_review`
- All children are closed (epic complete)
- Stop requested
- No active peasants remain but open work still exists

If none of those is true and peasants are only `working` / `awaiting_council`, the harness idles.

**WAITING status:** Add `WAITING` as a valid lord return status alongside DONE/CONTINUE/BLOCKED/ESCALATE. When the agent is called and determines nothing is actionable, it returns `STATUS: WAITING` — the harness treats this like CONTINUE but applies a longer delay before the next cycle. Handles edge cases where the harness can't tell if a state change is truly actionable.

**Why not `kd lord sleep` or `kd lord wait-for-change`:** Both still burn a model call to discover there's nothing to do. Wrong layer — scheduling is harness policy, not an agent tool.

## Acceptance Criteria

- [ ] Harness compares state snapshot before each cycle and skips LLM call when nothing changed
- [ ] Backoff delay increases when consecutive cycles show no change (cap at 60s)
- [ ] Backoff resets immediately when state changes
- [ ] `WAITING` is a valid lord return status that triggers longer delay
- [ ] Idle skips are logged to stdout/logs (heartbeat) but NOT to the epic worklog
