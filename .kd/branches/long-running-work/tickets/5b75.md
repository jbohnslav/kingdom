# Lord runtime log cleanup: eliminate double-print and fix log naming

Three related issues in lord runtime logging:

1. **Double-printing**: lord_harness.py uses both `logger.info()` and `print()` for the same events (idle skips, backoff, cycle summaries). Because lord_worker.py routes logging to stdout, both land in stdout.log — every message appears twice.

2. **Misleading log names**: `agent-live.log` is raw backend JSON deltas (746KB of streaming events), not the "per-cycle narration" the prompt claims. `stdout.log` is where human-readable output actually goes. The prompt at lord_harness.py:512 says narration is "captured in agent-live.log" which is wrong.

3. **Fix**: Remove duplicate print() calls where logger.info() already covers it (or vice versa). Update prompt text to match actual log destinations. Consider renaming logs or adding a comment explaining what each file contains.
