# PR #37 review: lord livelock bug + cycle counting + minor fixes

Claude's PR #37 review surfaced these issues. Council (claude + codex) reviewed and unanimously agreed on all six. Thread: council-c7ca.

## 1. Bug: Livelock when a peasant fails mid-work (HIGH)
`get_active_peasants` includes terminal states (failed, stopped) as "active". If a peasant fails with ticket still in_progress, `has_actionable_work` returns False (non-empty active list prevents stuck-state detection), and the lord idles forever.

Root cause: `get_active_peasants` mixes "in-flight", "reviewable", and "terminal" into one helper. Two call sites use it with different intent — `has_actionable_work` wants truly-active-for-scheduling, `build_lord_prompt` wants all-with-sessions-for-display.

Fix approach (council consensus):
- Use `ACTIVE_PEASANT_STATUSES` from `session.py` ({working, awaiting_council, needs_king_review}) instead of `not in ("idle",)`
- Split or rename: `get_inflight_peasants()` for scheduling vs display-oriented usage in `build_lord_prompt`
- Codex: exclude `needs_king_review` from "active" since `get_completed_peasants` already owns it
- Claude: `build_lord_prompt` still needs to show failed/stopped peasants — so either split the function or have `has_actionable_work` filter the list itself

## 2. max_cycles counts idle iterations, not LLM calls (MEDIUM)
The loop increments cycle on every iteration including idle skips. With 200 max_cycles and 60s backoff, the lord can exhaust its budget in ~3.3 hours without many actual LLM calls.

Fix approach (council consensus):
- Track `llm_calls` separately for the budget cap (rename current `max_cycles` intent)
- Keep an outer hard iteration cap (high, e.g. 1000+) so a dead epic doesn't idle forever
- Codex: two explicit caps — `max_iterations` (loop safety) + `max_agent_calls` (LLM budget)

## 3. kd lord stop misses "stopping" status (LOW)
Second call to `kd lord stop` fails with "not running (status: stopping)". Should say "Lord is already stopping" and exit 0. Small standalone fix.

## 4. Opportunistic cleanup (NEGLIGIBLE — fix if touching these lines)
- `filter_worklog_lines` initializes `include_current = True` — lines before first bullet included unconditionally
- Signal handler `frame` should be `types.FrameType | None` not `object`

## Acceptance Criteria

- [ ] Livelock bug fixed: failed/stopped peasants not counted as active in scheduling logic
- [ ] get_active_peasants split or renamed so scheduling vs display semantics are clear
- [ ] max_cycles only counts actual LLM calls; separate outer iteration safety cap retained
- [ ] kd lord stop handles 'stopping' status gracefully (exit 0, friendly message)
