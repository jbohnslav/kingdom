### 2026-08-03 — Real Claude/Codex run found and fixed cross-host attribution

Installed the full nine-event Claude hook set in this checkout and installed the
real Kingdom Codex plugin into the personal marketplace. Local versions exercised:
Claude Code `2.1.220`, Codex CLI `0.146.0-alpha.9.2`, Cursor Agent
`2026.02.27-e7d2ef6`, and Kingdom `0.6.0` from the working tree. Claude OAuth and
Codex authentication both completed real noninteractive agent turns.

The first isolated two-host run exposed a real bug: the Claude subprocess inherited
the owning Codex task's `CODEX_THREAD_ID`, while Claude's SessionStart response only
added model context and did not persist its own shell identity. The Claude ticket
was consequently attributed to the parent Codex context. Added a failing regression,
then used Claude's documented `CLAUDE_ENV_FILE` SessionStart contract to persist
shell-quoted `KD_CONTEXT` and `KD_HOST`. The corrected real Claude rerun now owns
ticket `76b8` as `claude:01cbbe4b`; the simultaneous Codex run owns ticket `9958`
as `codex:02d013d1`. Their current-ticket queries and worklogs stayed distinct.

The host audit found a second cross-host collision: per-turn Stop state used only
the raw session string for its filename. Identical IDs from different hosts could
share `had_work`, `did_log`, or `stop_blocked` despite having host-qualified ticket
contexts. A red-first three-host regression reproduced the single-file collision;
turn state is now keyed by host plus session digest, matching checkpoint isolation.
An environment-file write failure is also covered as a visible, fail-open warning.
