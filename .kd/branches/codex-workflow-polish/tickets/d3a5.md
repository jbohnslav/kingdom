# Host integrations, subagent attribution, and compaction durability

Kingdom should use native host lifecycle and subagent facilities where they exist,
while keeping one small internal event model. The durable ticket is the source of
truth; host-specific agent/thread APIs are adapters, not a new orchestration layer.

## Acceptance Criteria

- [x] Claude and Codex sessions resolve a stable Kingdom context without relying on branch recency.
- [x] Supported native subagents inherit or receive an explicit ticket assignment.
- [x] Ticket provenance records the host, parent context, and subagent identity without leaking prompts.
- [x] A ticket checkpoint is requested before compaction and at session handoff where host hooks allow it.
- [x] Cursor support is based on a capability spike, with unsupported behavior documented honestly.
- [x] Hook failures never block the host from exiting or corrupt a ticket.
