# Make command-rich worklog guidance shell-safe

## Acceptance Criteria

- [x] Kingdom's agent-facing workflow shows a shell-safe way to append notes
  containing Markdown backticks, command substitutions, quotes, or multiline
  text.
- [x] The short inline `kd tk log` example clearly limits itself to plain text;
  command-rich notes route to stdin or direct Markdown editing.
- [x] A regression or documentation check preserves the safe example.
- [x] The guidance remains concise enough that agents follow it during the core
  loop rather than discovering it only in recovery documentation.

## Context

During ticket `b507` live dogfooding, two independent Codex workers passed notes
containing Markdown-backticked commands inside a double-quoted shell argument to
`kd tk log`. The shell evaluated those backticks before Kingdom received the
message. One note embedded an entire unrelated status command's output in the
ticket; the other worker also had to append a correction for a shell-substituted
entry. Kingdom already supports stdin when the message argument is omitted, and
the skill recommends direct ticket editing for rich notes, but its prominent
quick example uses a quoted inline argument without warning about shell
metacharacters.

This is primarily a workflow-guidance defect because no CLI can recover content
that the shell substituted before process launch. Prefer a safe stdin/direct-edit
pattern over building new quoting machinery.
