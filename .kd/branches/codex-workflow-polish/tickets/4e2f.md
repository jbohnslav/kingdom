# Prove multi-epic dependency scheduling and lord coordination

The roadmap spans five epics, but existing lord tests exercise one epic at a time.
Code inspection shows that leaf dependency status is read from every ticket on the
branch and each lord owns only its epic's direct children. A completed lord session
does not itself close the epic ticket, so epic-to-epic dependency edges require
manual closure and are unsafe as automatic release gates.

## Acceptance Criteria

- [ ] An integration fixture contains at least two epics with a cross-epic leaf dependency.
- [ ] Two simultaneous lords never launch the same peasant or start a blocked child.
- [ ] Closing the external leaf dependency wakes the blocked lord and makes its child startable.
- [ ] Lord completion, epic ticket closure, and downstream readiness have explicit tested semantics.
- [ ] Concurrent peasant accepts and branch/worktree merges are serialized or fail recoverably.
- [ ] The test covers stop/restart while another epic continues.
- [ ] The roadmap uses leaf-level release gates until epic-level closure is proven reliable.
