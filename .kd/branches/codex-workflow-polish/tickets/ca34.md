# Track native subagents on inherited or explicitly assigned tickets

Use the host's own subagent machinery while keeping ticket ownership and provenance
visible in Kingdom. Inheritance should be effortless; a separate assignment should
be explicit.

## Acceptance Criteria

- [x] A subagent inherits the parent context's ticket by default when the host reports parentage.
- [x] A supported hook/API can assign a subagent to a different ticket intentionally.
- [x] Status/TUI distinguishes the owning session from active native subagents.
- [x] Concurrent worklog writes are atomic and attributed by host/agent identity.
- [x] Subagent completion appends a concise handoff without closing the owner's ticket.
- [x] Missing host events degrade to ordinary session logging, not guessed attribution.
