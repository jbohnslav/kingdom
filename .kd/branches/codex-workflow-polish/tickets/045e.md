# Deprecate tk move and define the supported defer-return flow

Remove arbitrary location mutation from the primary workflow. Before deletion,
define what a user should do when pulled work must be deferred or returned.

## Acceptance Criteria

- [ ] Current `tk move` use sites, tests, and recovery scenarios are inventoried.
- [ ] A single explicit defer/return behavior is chosen, or the need is rejected with rationale.
- [ ] The replacement preserves history and clears context bindings safely.
- [ ] `tk move` warns for a compatibility window and points to the replacement.
- [ ] Removal timing and migration are documented.
