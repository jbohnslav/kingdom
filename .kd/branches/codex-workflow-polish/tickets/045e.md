# Deprecate tk move and define the supported defer-return flow

Remove arbitrary location mutation from the primary workflow. Before deletion,
define what a user should do when pulled work must be deferred or returned.

## Acceptance Criteria

- [x] Current `tk move` use sites, tests, and recovery scenarios are inventoried.
- [x] A single explicit defer/return behavior is chosen, or the need is rejected with rationale.
- [x] The replacement preserves history and clears context bindings safely.
- [x] `tk move` warns for a compatibility window and points to the replacement.
- [x] Removal timing and migration are documented.

## Worklog

- 2026-08-03 — Inventory/design pass only; no implementation changes. The public
  `ticket_move` command in `src/kingdom/cli/ticket.py` is a global source lookup
  plus arbitrary destination selector. It supports backlog, the active branch,
  any named branch, the `branch` keyword, a legacy positional target, multiple
  IDs with two-pass validation, destination idempotence, and an active-peasant
  guard. It moves the Markdown file without changing status, assignee, lifecycle
  history, or execution/terminal binding locations. That last property is unsafe
  for native contexts: an `in_progress` ticket can move while its context JSON
  still points to the old branch. Only active peasant sessions are blocked.

- 2026-08-03 — Test/use-site inventory: `TestTicketMove` has nine CLI cases
  covering current-branch defaulting, backlog return, idempotence, missing current
  branch, `--to branch`, nonexistent targets, cross-branch moves, and active vs
  completed peasants. `TestMoveTicket` has five lower-level rename/cross-filesystem/
  collision tests; those remain necessary because pull, close/archive,
  reopen/restore, and peasant auto-pull all use the internal `move_ticket` helper.
  User-facing references remain in `kd done` recovery output and its test, the
  session-start hook brief/reminder, `skills/kingdom/SKILL.md`, and
  `skills/kingdom/references/tickets.md`. Historical docs/tickets show three real
  jobs: selecting backlog work before `tk pull` existed, returning unfinished
  branch work so `kd done` can finish, and re-homing work after a branch/context
  switch. They also record duplicate-source, destination, misleading-label,
  current-branch-default, and active-peasant failures that compatibility tests
  must retain.

- 2026-08-03 — Recommendation for council/King review: add one explicit
  `kd tk defer ID... --reason TEXT` transition. It may resolve a ticket from any
  live branch (so branch A → B recovery is `defer`, then `pull` while on B), but
  its only destination is backlog. Validate the whole batch before mutation;
  closed/archived tickets and active peasants conflict, and an `in_progress`
  ticket owned by another execution context must be deferred by its owner. A
  successful defer records timestamp, actor/context, source branch, previous
  status/assignee, and the required reason in `## Lifecycle`; then sets status to
  `open`, clears assignee plus all execution and legacy terminal bindings, and
  moves the same ticket Markdown to backlog. Dependencies, links, parent, and all
  existing body/history remain intact. A ticket already in backlog is an
  idempotent no-op and must not duplicate lifecycle history.

- 2026-08-03 — Compatibility recommendation: in 1.0, emit one stderr warning per
  `tk move` invocation: the command is deprecated, will be removed in 2.0, and
  backlog→work uses `tk pull` while work→backlog uses `tk defer`. Delegate
  `--to backlog` to defer (using an explicit compatibility lifecycle reason) and
  backlog→current-branch moves to pull. Keep arbitrary branch→branch and
  backlog→noncurrent-branch movement operational for the 1.x window, but warn
  with the migration sequence `tk defer ID --reason ...; switch/check out the
  target; tk pull ID`, and refuse to relocate active native/peasant-owned work.
  Update `kd done`, the hook reminders, and both live skill references immediately;
  historical `.kd` records stay untouched. Remove only the CLI command in 2.0;
  retain the internal `move_ticket` primitive. Release/migration docs should map
  each legacy command shape to pull/defer and state that defer deliberately resets
  work to open/unassigned while retaining a lifecycle entry.
