# Checkpoint tickets before compaction and at session handoff

Turn the user's manual "thoroughly update your ticket" instruction into a host
lifecycle behavior wherever a reliable pre-compaction or session-end hook exists.

## Acceptance Criteria

- [x] Pre-compaction asks the active agent to record decisions, completed work, verification, blockers, and next steps.
- [x] Session-end produces the same structured handoff when the host permits agent output.
- [x] The checkpoint targets the exact context binding and never the most recent branch ticket.
- [x] Repeated hook calls are idempotent enough to avoid duplicate boilerplate.
- [x] Hook timeouts/failures warn but do not block compaction or session exit.
- [x] Hosts without a pre-compaction interception point have a documented manual fallback.

## Worklog

- 2026-08-03 — Started after the Codex/Claude adapters landed. The official
  hook contracts can surface a checkpoint request but cannot safely synthesize
  decisions or verification from an unstable transcript format. Implementing a
  content-free pending-checkpoint record keyed by the exact execution context:
  ask before compaction/session end, repeat after compaction or compact-resume,
  clear only after that context edits/logs a ticket, and never fall back to the
  branch's most recent ticket.
