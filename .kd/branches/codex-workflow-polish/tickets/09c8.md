# Migrate branch-global current-ticket state compatibly

Introduce session-scoped bindings without invalidating repositories created by
older Kingdom releases.

## Acceptance Criteria

- [x] Old terminal-context and branch-current state is detected without crashing.
- [x] Migration preserves ticket IDs, status, and worklog Markdown; only generic legacy assignment is replaced by exact context assignment.
- [x] Ambiguous branch-global state is reported for user choice instead of guessed.
- [x] The migration is idempotent and has a documented rollback path.
- [x] Fixtures cover pre-context, v0.6 terminal-context, and partially migrated repositories.

## Migration Contract

Migration happens lazily on `kd tk current`. An exact v0.6 terminal binding wins;
otherwise a single `in_progress` branch ticket with no assignee or generic `hand`
assignment can migrate. Two or more candidates are never guessed. The ticket file
stays in place with the same ID, status, and Markdown; only its generic assignee is
replaced by the context ID.

The old terminal-context JSON is retained unchanged and every migration is
idempotent. Rollback therefore consists of using the previous Kingdom version; it
continues to see the original terminal binding and branch ticket. The ignored
`.kd/runtime/contexts/` records may be discarded without altering ticket Markdown.
