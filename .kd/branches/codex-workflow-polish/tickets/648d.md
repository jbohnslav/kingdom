## Recommendation

Suggest a native subagent for a bounded child task when the host exposes a stable
parent/child identity, the child can work safely in the parent's checkout, and the
owning agent will review and run the final repository gate. This is the lower-cost
path for exploratory work, focused implementation, and tasks where rapid context
sharing matters.

Use a peasant when worktree isolation, long autonomous execution, a resumable exact
commit, or independent review is worth the additional tokens and operational
latency. Keep peasant → council as the default peasant flow: this run did not find a
code defect, but it did provide an independent read of the exact commit before a
conflict-prone integration. Fail fast on deterministic authentication errors and
make branch reconciliation reliable rather than weakening the review gate.

This is directional evidence only. The Codex packaging ticket was broader and
greenfield, the Claude ticket emphasized backward compatibility, only the peasant
used a worktree and council, model/token telemetry was unavailable, and concurrent
owner work blurred the native task's commit boundary.
