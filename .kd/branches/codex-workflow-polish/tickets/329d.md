# Ticket-first workflow and deliberate autonomy

Reframe Kingdom around the behavior that earns daily use: agents leave durable,
useful Markdown tickets. Epics organize outcomes; design docs are optional; direct
work, native subagents, peasants, lords, council, and the TUI remain deliberate
tools rather than mandatory stages.

## Acceptance Criteria

- [ ] The skill checks current context and related tickets before creating a new ticket.
- [ ] The skill explains when to work directly, delegate natively, use a peasant/lord, or consult council.
- [ ] Peasant-to-council review remains the default autonomous-worker policy.
- [ ] `kd start` is idempotent for an existing workspace and does not force design ceremony.
- [ ] Help, status, README, and TUI lead with tickets, epics, and active contexts.
- [ ] Low-value commands are deprecated only with an explicit replacement and compatibility window.
