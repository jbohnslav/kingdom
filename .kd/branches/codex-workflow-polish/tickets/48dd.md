# Explicit closure, backlog flow, and ticket mutation cleanup

Make ticket state say what actually happened. Pulling starts planned work; closing
records an outcome. Arbitrary file-location movement and overlapping note commands
should not masquerade as lifecycle concepts.

## Acceptance Criteria

- [ ] `kd tk close` records a typed resolution and human-readable reason.
- [ ] Completed, won't-do, duplicate, and superseded work remain distinguishable.
- [ ] `kd done` accepts valid terminal resolutions and reports their breakdown.
- [ ] `tk pull` remains the canonical backlog-to-active transition.
- [ ] `tk move` and `add-note` have clear compatibility/deprecation paths.
- [ ] Existing ticket Markdown remains readable and migrates without data loss.
