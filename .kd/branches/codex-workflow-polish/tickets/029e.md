# Session-scoped ticket assignment and agent identity

"Hand" is not a useful product abstraction. The actual need is simpler: several
Claude, Codex, Cursor, terminal, peasant, and lord sessions may work concurrently,
and each needs a stable identity and exact active-ticket binding. Model execution
contexts directly and reserve role-flavored names for optional presentation.

## Acceptance Criteria

- [x] Agent sessions have explicit, host-namespaced identity.
- [x] Multiple sessions can work concurrently on different tickets on one branch.
- [x] `kd tk start` assigns to the calling execution context.
- [x] `kd status` and `kd tk list` show session/ticket assignments and agent roles without requiring a Hand concept.

## Plan

Treat a host execution context—not a role name or branch—as the binding unit. A
context must be stable for a session, portable across Claude/Codex/terminal hosts,
and explicit enough that Kingdom never guesses between several in-progress tickets.

Child tickets:

- `e204` — portable context identity and persistence
- `f122` — context-aware `tk start` and `tk current`
- `539b` — concurrent session visibility in status and TUI
- `09c8` — backward-compatible state migration
- `7070` — same-branch concurrency integration tests
