# Prevent development dogfooding with a stale installed kd binary

During `f122`, bare `kd tk current` continued running the installed release and
reported the branch-global ticket with `assignee: hand`, while
`uv run --project … kd` correctly exercised the working-tree implementation. This
is especially dangerous in a self-hosting project because commands succeed and
produce plausible but stale results.

## Acceptance Criteria

- [ ] Development docs and the repo skill identify the canonical checkout invocation.
- [ ] A developer gets a visible version/source mismatch warning when bare `kd` is stale, or setup makes the checkout command authoritative.
- [ ] Tests cover the chosen version/source detection without depending on network access.
- [ ] Dogfood and release instructions consistently exercise working-tree code.
- [ ] Normal installed-user workflows remain quiet and unchanged.
