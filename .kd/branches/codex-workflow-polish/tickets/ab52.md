# Reframe README and CLI help around tickets, epics, and contexts

Make the public mental model match observed daily value. Advanced autonomy remains
visible, but does not crowd out the durable-ticket loop.

## Acceptance Criteria

- [x] README starts with create/find, pull/start, log, close, and epic organization.
- [x] Help explains contexts and concurrent agent sessions with one concrete example.
- [x] Design docs are described as optional; TUI, council, peasants, and lords remain documented power tools.
- [x] Examples show direct work and native subagent delegation as well as a reviewed peasant run.
- [x] Deprecated commands have replacements and removal versions.
- [x] Documentation examples are executed in CI or a release check where practical.

## Worklog

### 2026-08-03 — Public-surface audit and implementation boundary

Current README opens with council/design/peasant concepts and makes the
design-first autonomous flow its first concrete workflow. Root `kd --help`
contains only “Kingdom CLI.” and `kd status --help` still promises design and
breakdown status, even though the useful human output is ticket counts plus
concurrent execution contexts. Human status and TUI branch context label those
bindings generically as “Sessions,” without explaining that each concurrent
agent context can own a different ticket.

`scripts/smoke.sh` still calls `uv run kd breakdown`, a removed top-level path,
and mutates the current checkout's `.kd` session instead of exercising examples
in an isolated repository. CI and release workflows do not run the smoke script.

Implementation boundary: reframe copy and examples without changing the hidden
but callable `kd design` behavior owned by `3732`. Preserve `b529`'s exact staged
migrations (`move` → pull/defer/defer-switch-pull, removal v1.0.0; hidden
`add-note` → `log`, removal v0.8.0). Keep JSON status compatibility fields while
removing design from the human-first status story. Build a self-contained smoke
repository that executes the practical ticket/epic loop and run it in CI and
before release publication; external agent launches remain documented but are
not suitable for deterministic smoke execution.

Compatibility clarification from review: preserve discoverability when a real
design document exists. Human status will show it only as a trailing
`Optional design:` line after the ticket/context/assignment story; missing or
incomplete design state stays out of the default output. JSON compatibility and
`kd design` behavior remain unchanged.
