# PR #28 second review: worktree cleanup bug and minor fixes

Claude's second review of PR #28 found a real bug and several minor issues.

## Bug

1. **kd done worktree cleanup checks the wrong path** — `done()` looks for worktrees at `.kd/worktrees/<branch-name>/` but `worktree_path_for()` stores them at `.kd/worktrees/<ticket-id>/` (flat). These paths never match, so worktree cleanup silently does nothing. Fix: read from `state.json["worktrees"]` map (already tracked by `create_worktree`).

## Minor

2. **ticket_undep uses substring match** (cli.py:4033) — `[d for d in ticket.deps if depends_on in d]` means passing `a` could remove multiple deps. Should use `find_ticket()` for proper ID resolution like `ticket_dep` does.

3. **ticket_closed sorts by creation date, not close date** — Users expect recently-closed-first. Ticket model lacks `closed_at` field, so this is a data model limitation. Consider adding `closed_at` timestamp.

4. **council_review defaults to "master"** — Repos using `main` will silently fail. Detect `main` vs `master` (check if `origin/main` exists).

5. **write_json comment says "pid + thread id" but only uses pid** (state.py:141) — Comment is misleading. Either update comment or add `threading.get_ident()`.
