# Bug: ThinkingPanel id reassignment crash in kd chat

## Description

`kd chat` crashes with `ValueError: Node 'id' attribute may not be changed once set` when a codex response completes.

At `app.py:957`, `handle_new_message()` tries to reassign `thinking_panel.id` from `"thinking-codex"` to `"thinking-codex-3"`. Textual's `DOMNode.id` setter raises if the id is already set (since Textual enforces immutable ids after initial assignment).

The ThinkingPanel is created with `id="thinking-codex"` during stream start, and the code assumes it can rename the id on finalization. This worked in an older Textual version but current Textual prohibits it.

## Fix

Instead of reassigning the id, either:
- Create the ThinkingPanel with the final id from the start (e.g. `thinking-{member}-{sequence}` — but sequence isn't known at stream start)
- Remove and remount the panel with the new id
- Skip the id rename entirely — the thinking panel doesn't need a sequence-specific id once the message is finalized

- [ ] `kd chat` does not crash when a codex (or any member) response with thinking tokens completes
- [ ] ThinkingPanel id is never reassigned after mount
- [ ] Regression test covering this path
