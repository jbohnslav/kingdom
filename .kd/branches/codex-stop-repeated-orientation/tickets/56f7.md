# Stop agents repeating ticket discovery on routine follow-ups

Agents use Kingdom too mechanically: they repeat orientation commands on routine
follow-ups and append logs instead of maintaining the raw ticket Markdown. The
initial discovery-checklist fix is complete in 86033bf. Current work implements
the approved outcome-based skill and hook changes and prepares release 1.1.0.
Modern LLMs with strong instruction following mostly need less instruction;
overly strict procedures can undermine judgment.

Approved direction: make the ticket body the current working document, reserve
the worklog for meaningful history, replace procedural mandates with outcomes,
move recipes into references, and shorten the per-turn hook. Replace the Stop
block with a nonblocking reminder, as the King explicitly chose after reviewing
the council advice. Preserve lifecycle semantics and handoff checkpoints.

Release requirement: include a minor version bump from 1.0.2 to 1.1.0 with the
agreed fix, and publish the release after verification so updating users receive
the changes. Publication and installed-package verification are tracked separately in 268d so
the implementation can pass the required pre-merge terminal-ticket gate. The
version bump alone does not fulfill release publication.

## Council Findings and Proposed Direction

Council thread: council-d803 (Claude and Codex). Both support less procedural
instruction and agree that contradictory incentives, not just length, are the
central problem. The skill and reminders route current findings into history;
the session brief tells agents to create tickets for scope changes. The Stop
hook explicitly prescribes kd tk log even though direct ticket edits satisfy
its gate. This was verified in handle_post_tool_use and handle_stop.

Recommendation for discussion: make semantic Markdown edits the default for
current scope, plan, findings, and acceptance criteria; use logs for meaningful
history and evidence; retain kd commands for lifecycle and structured
relationships because they manage validation, bindings, and side effects.
Shorten the core skill and both reminder texts together with removing the
per-turn logging block. Keep preservation checks at real handoff/compaction
boundaries and completion evidence under repository policy.

Difference: Claude prefers replacing the Stop block with a nonblocking nudge
(or removing it); Codex recommends removal and retaining targeted handoff
checkpoints. Claude stresses surfacing substantive changes to user requirements;
Codex stresses moving generic testing and workflow mandates to repository policy.
Both distinguish file evidence from the unproven general claim about model
behavior. The King selected the nonblocking reminder and authorized implementation.

## Implementation and Verification

The core skill now describes outcomes, direct Markdown editing, and judgment.
Ticket recipes remain in the reference; README and host support docs match.
Claude/Codex Stop emits only systemMessage, once per turn, and never blocks.
Cursor has no advisory Stop channel, so it emits nothing rather than triggering
another turn. Session/prompt reminders no longer prescribe logging commands.
Lifecycle and compaction/handoff behavior are preserved.

Validation: 2291 passed, 1 xfailed with Textual integration; Ruff and all
pre-commit checks passed; CLI smoke reached readiness; 1.1.0 wheel and sdist
passed Twine. Manual hook CLI smoke showed the revised messages, a single
advisory Stop, and a silent duplicate Stop. The wheel reports version 1.1.0.
The checkout-wide doctor found historical closure metadata issues, tracked
separately; no historical ticket resolutions were rewritten.
