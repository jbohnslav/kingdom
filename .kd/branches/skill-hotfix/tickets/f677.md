# peasant show: commit range uses normalized branch name instead of real git ref

ctx.feature in peasant commands comes from resolve_current_run(), which returns the **normalized** branch name (slashes→dashes, lowercased). When used as a git ref in peasant_show's commit range (peasant.py:552):

    log_spec = [f"{ctx.feature}..{branch_name}"]

...this fails silently for branches with slashes (e.g. feature/oauth-refresh → feature-oauth-refresh is not a valid git ref). git log exits non-zero, and the command falls back to "(no commits)" even when the peasant has real commits.

The original branch name is stored in state.json["branch"] but never surfaced through resolve_peasant_context.

**Repro:** Create a branch with a slash (e.g. `feature/test`), run `kd start`, start a peasant that makes commits, then `kd peasant show` — commit section will be empty.

**Fix:** Either store the original branch name alongside the normalized one in PeasantContext, or look it up from state.json when building git refs. The normalized name should only be used for directory paths, never as a git ref.

Source: Codex automated review of PR #33, round 2 (P1).
