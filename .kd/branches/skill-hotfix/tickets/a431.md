# Eliminate duplicate skill files: symlink src/kingdom/skill/ to skills/kingdom/

Two copies of the kingdom skill exist in this repo:

1. `skills/kingdom/SKILL.md` (+ references/) — the canonical dev copy, symlinked from ~/.claude/skills/kingdom during dev, and where all editing happens
2. `src/kingdom/skill/SKILL.md` (+ references/) — the packaged copy, shipped inside the Python package so install_skill() can use importlib.resources to copy it to end-user machines

Nobody enforced sync between them. The packaged copy is ~100 lines behind the repo copy with ghost commands (kd tk dep, kd init, kd tk ready) and contradictory guidance. When users run `uv tool update kingdom` and `kd start`, install_skill() faithfully copies the STALE packaged version.

Fix: replace every .md file under `src/kingdom/skill/` with a symlink to its counterpart under `skills/kingdom/`. This is the same pattern used for AGENTS.md -> CLAUDE.md. setuptools follows symlinks, so the package-data declaration in pyproject.toml stays as-is.

Important follow-through: this only eliminates the duplicate source content if the installer also stops hard-coding a fixed reference file list. Today `install_skill()` copies exactly three named files (`council.md`, `peasants.md`, `tickets.md`). If a fourth reference file is added later, we recreate the drift problem in a new form. The installer should copy `references/*.md` dynamically from the packaged directory.

Concrete changes:
- `src/kingdom/skill/SKILL.md` -> symlink to `../../../skills/kingdom/SKILL.md`
- `src/kingdom/skill/references/council.md` -> symlink to `../../../../skills/kingdom/references/council.md`
- `src/kingdom/skill/references/peasants.md` -> same pattern
- `src/kingdom/skill/references/tickets.md` -> same pattern
- Keep the `__init__.py` files (needed for importlib.resources)
- Update `install_skill()` to copy reference markdown files dynamically from the packaged `references/` directory instead of a fixed filename tuple
- Verify `uv build` still includes the skill files in the wheel
- Verify `install_skill()` still works after the change

Why symlinks over a build hook:
- Zero maintenance, single source of truth, no build tooling changes
- Proven pattern already in this repo (AGENTS.md)
- The package-data config in pyproject.toml (`kingdom.skill = ["*.md", "references/*.md"]`) works unchanged

Why not just delete src/kingdom/skill/ and point importlib at skills/kingdom/:
- importlib.resources requires files inside a Python package namespace (kingdom.skill)
- skills/kingdom/ is outside the package tree
