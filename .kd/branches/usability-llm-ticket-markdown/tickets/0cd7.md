# kd peasant accept should auto-clean worktree after successful merge

`kd peasant accept` merges and closes the ticket but leaves the worktree directory and branch behind. There's no reason to keep a worktree after a successful accept — it should be cleaned up automatically as part of the accept flow. This affects both the lord and manual usage.

## Acceptance Criteria

- [x] `kd peasant accept` removes the worktree and deletes the ticket branch after successful merge + close
- [x] Cleanup failure (e.g. worktree already removed) is a warning, not an error — the accept still succeeds
- [x] No separate `kd peasant clean` step needed after accept

## Worklog

- Added best-effort accept cleanup for worktree-mode peasants: after closing the ticket and marking the session done, `kd peasant accept` removes the peasant worktree and deletes the `ticket/<id>` branch.
- Cleanup is intentionally non-fatal. Missing worktrees, failed worktree removal, or failed branch deletion emit warnings while accept still succeeds.
- Hand mode skips cleanup because there is no disposable peasant worktree or ticket branch to remove.
- Added tests for successful cleanup and cleanup failures that warn without failing accept.
