# Do not reuse peasant resume_id across backend changes

GitHub issue #43: Changing peasant backend after a failed run can preserve an incompatible resume_id.

When a failed peasant session has a saved resume_id from one agent backend, and config changes so the restarted peasant uses a different backend, Kingdom should not pass the stale resume_id to the new backend.

This ticket starts by adding failing unit tests that capture the expected behavior before implementing the fix.

Issue: https://github.com/jbohnslav/kingdom/issues/43

## Acceptance Criteria

- [x] Regression tests cover restarting a failed peasant with a different agent backend.
- [x] Tests assert stale resume_id is not reused when the backend changes.
- [x] Tests fail against the current implementation before the fix.
