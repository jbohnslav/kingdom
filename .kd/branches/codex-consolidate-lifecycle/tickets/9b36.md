# Address actionable Claude review findings for PR #54

## Acceptance Criteria

- [x] `kd peasant accept` cannot merge a worker branch into an unrelated Git branch; integration targets remain explicit and compatible with 1.0 workspace selection.
- [x] Leaving `in_progress` through `kd tk status` or `kd tk reopen` clears stale native ownership so nonterminal tickets remain visible in `kd status`.
- [x] `duplicate` and `superseded` closures validate their required reference before writing terminal ticket state.
- [x] stale execution-context pruning cannot delete a live terminal-context binding that happens to name the same ticket and workspace.
- [x] all ticket mutation paths participate in one coherent per-ticket locking protocol without deadlocking nested helpers.
- [x] execution-context record creation participates in the same per-context locking protocol as refresh, finish, and clear operations.
- [x] worktree bookkeeping handles the actual JSON, filesystem, and lock failures raised by its state helper consistently.
- [x] hook checkpoint completion parses the exact `kd tk log`/`kd ticket log` ticket argument instead of accepting a substring elsewhere in the command.
- [x] `kd tk close` and `kd tk reopen` turn malformed execution-context identifiers into concise CLI errors rather than tracebacks.
- [x] each accepted finding has a red-first regression, focused verification, and durable evidence; the full suite, pre-commit, smoke workflow, and `uv run kd status --check` pass before closure.

## Review Findings

1. [Peasant acceptance can merge into the wrong checked-out branch](https://github.com/jbohnslav/kingdom/pull/54#discussion_r3817170772).
2. [`tk status` can retain a stale assignee and hide the ticket from `kd status`](https://github.com/jbohnslav/kingdom/pull/54#discussion_r3817171512).
3. [`duplicate` and `superseded` closure references are not validated before write](https://github.com/jbohnslav/kingdom/pull/54#discussion_r3817172186).
4. [Stale-context pruning can delete a live terminal binding](https://github.com/jbohnslav/kingdom/pull/54#discussion_r3817172505).
5. [`write_ticket` bypasses the per-ticket lock used by sibling mutation helpers](https://github.com/jbohnslav/kingdom/pull/54#discussion_r3817172882).
6. [Worktree bookkeeping catches an exception type its state helper does not raise](https://github.com/jbohnslav/kingdom/pull/54#discussion_r3817173360).
7. [Checkpoint completion uses a bare ticket-ID substring match](https://github.com/jbohnslav/kingdom/pull/54#discussion_r3817173608).
8. [`tk close` and `tk reopen` do not guard context-validation errors](https://github.com/jbohnslav/kingdom/pull/54#discussion_r3817173821).
9. [Execution-context creation writes outside the per-context lock](https://github.com/jbohnslav/kingdom/pull/54#discussion_r3817175503).

## Non-goal

Do not restore or enable the legacy Stop-hook heuristic fallback discussed in
[Claude's tenth thread](https://github.com/jbohnslav/kingdom/pull/54#discussion_r3817171866).
Kingdom 1.0 intentionally requires exact execution-context ownership; an
unbound branch-level guess must not silently substitute for that model.
