# Replace branch completion with status readiness checks

Make ticket state the source of truth for workspace readiness. Remove the
top-level `kd done` transition and expose its useful validation as a read-only
status check suitable for humans, scripts, and release gates.

## Acceptance Criteria

- [x] `kd status --check` exits nonzero when current workspace tickets remain nonterminal.
- [x] The check rejects malformed terminal-resolution evidence and reports actionable details.
- [x] Human and JSON status expose the same readiness result without mutating workspace state.
- [x] The public `kd done` command and its `--force` bypass are removed.
- [x] Existing legacy `status: done` workspaces remain readable without creating new done-state writes.
- [x] Focused tests are written red-first and pass after implementation.
